# 隐私告知、资料检查和运行告警

## 首次上线前

1. 负责人填写 `PRIVACY_OPERATOR`（真实运营主体）、`PRIVACY_CONTACT`（数据请求联系方式）、`PRIVACY_MODEL_PROVIDER`（实际模型服务商，包括网关背后的供应方）。核对服务商处理地点、留存与训练政策，以及本站日志和备份的留存、删除流程后，才能设置 `PRIVACY_REVIEWED=true`。这是人工确认，不自动证明法律合规；第三方、跨境等事项由运营主体确认适用要求。
2. 输入区保留简短隐私说明，不提供跳转链接；内部页面也不提供隐私跳转。`/privacy`、`/privacy/notice` 保留为可直接访问的说明接口。保留期取实际配置，默认游客咨询 24 小时、官网登录客户 90 天、事件 30 天。Cookie 与聊天记录保留期不同，清理任务约每 5 分钟执行，备份及网关日志不由该任务清理。历史列表支持删除会话，其他请求由公布的联系渠道处理。
3. 核对收集目的、字段范围、身份联动、人工跳转和模型传输说明。应用不主动要求身份证、银行卡等信息，但用户输入仍可能包含个人信息；提示勿输入不代表已经自动脱敏。

## 资料检查

执行 `python scripts/audit_materials.py --database`，检查课程事实、审核目录、课程正文文件及数据库中已发布/待审核片段。结果在 `data/operations/material-audit.json`，只显示规则编号、数量和文件/资料编号，不输出敏感原文。退出码非 0 表示仍有待处理项。

规则检查密钥、手机号/身份证样式、内部报价与保密标签、嵌入的越权指令。误报时整理成允许对外的资料再上传；不提供跳过扫描发布按钮。规则不能识别所有敏感内容及图片文字，必须逐页阅读原文件。

管理员下载原文，逐份确认：来源公开且可对外使用；无个人信息/密钥/内部合同或报价；商业信息由负责人核对；无要求模型忽略规则的指令。填写负责人确认依据后发布。后端重新扫描本次内容，失败时保留待审核状态和旧版本。历史已发布资料可点“复核安全并留档”，同样检查并追加记录；发现问题先撤回再重新整理。不得由自动化工具冒充负责人签字。

2026-10-10 本地只读检查：5 个本地文件及 7 份已发布资料没有命中本次规则；7 份历史资料缺少当前四项审核记录，仍需人工复核。这不是业务准确性或无敏感信息的保证；报告随实际库变化重新生成。结构化课程事实与审核清单仍由负责人单独核对。

## 启动监控

生成独立随机 `MONITORING_TOKEN`（至少 32 字符），API 与采集器使用同一个值，不复用登录或模型密钥。配置实际输入/输出每百万 Token 单价和每日预算：`MONITORING_INPUT_PRICE_PER_MILLION`、`MONITORING_OUTPUT_PRICE_PER_MILLION`、`MONITORING_DAILY_BUDGET`，使用同一种货币。缓存优惠、推理 Token 等供应商差异未自动结算，应与账单对账；缺配置或模型不返回用量会告警。

发布执行 `docker compose --env-file .env.deploy up -d --no-build api monitor`。独立进程每 60 秒检查 `/ready` 及独立凭证保护的 `/ops/metrics`，保存到 `data/operations/monitor-state.json`。管理账号可在内部维护页点击“查看最新告警”，或读取 `/metrics/alerts` 查看当前告警、恢复记录及费用估算；超出 3 个周期未更新会显示采集器失联。

默认触发：最近 5 分钟 HTTP/模型错误率达 5%（至少 5 次 HTTP 或 3 次模型调用），或 3 次 HTTP 服务端错误；出现模型超时；请求 P95 达 30 秒（至少 5 个样本）；429 达 20 次；当日估算费用达到预算。指标不含问题正文。P95 覆盖最近 5 分钟至多 10000 个请求；流式中断可能仍为 HTTP 200，模型错误另计。

触发/恢复写入日志，保留最近 1000 条变化，避免每分钟重复刷屏。`docker compose --env-file .env.deploy logs --tail 100 monitor` 查看。尚未绑定邮件、企业微信或短信通知；正式开放前指定值班人，由部署方接入日志告警平台。整个宿主机失联需外部平台探测。未授权时不向外部联系人发送消息。

费用为采样估算，不是账单或费用硬上限；监控停机、重启采样间隔内用量可能漏采，重启显示缺口告警。日预算按 UTC 日统计。目前仅支持单副本；超预算只告警，不自动中断模型调用。

## 告警和回滚验收

`python -m pytest -q tests/test_operations_safety.py` 验证错误、超时、慢请求、限流、费用、告警去重及恢复。`python scripts/recovery_drill.py` 使用临时容器和虚构资料验证停用、导出还原、文件恢复、全部表内容比对及危险降级保护；最终删除自己创建的容器。报告在 `data/operations/recovery-drill.json`，不连接当前 `.env` 的业务数据库，不复制真实会话到临时环境。

本地隔离演练通过；生产备份恢复、实际问答及上一版本镜像切换待预发布签收，按 [部署与回滚](DEPLOYMENT.md) 执行。开放前实际验证采集器启动、故障告警可见和值班人可收到部署方通知；自动测试不能替代这些步骤。
