## 执行约束与已完成基础

保留自研的课程审核、适配规则、实时商业事实、购买门禁、咨询所有权和回答快照。不因成熟平台功能更多而整套迁移，不新增订单、支付、会员等级或通用工作流。

已有 PostgreSQL + pgvector 集成 CI、Alembic `0004`、统一游客/客户所有者、当前游客咨询原子关联、前端身份清理和默认关闭的 `/miniapp/me` 验证适配器。

10/10 已补齐 `/admin` 资料维护、候选上传、人工审核发布及记录、同课程原文替换和撤回。上传不会自动生效；不同内容的新版发布前旧版保持可用。全部生成依赖在生成前后、历史保存、缓存重放与输出前验证，撤回后丢弃在途答案并清除前端分段内容。并发发布、生成期间撤回及输出锁已通过真实 PostgreSQL 回归。尚未部署或升级项目运行库，事实编辑、完整版本适用范围和生产容量验证仍未完成。

官网暂时无法修改，且未加载助手脚本。真实凭据传递、退出撤销和客户端到端验收暂缓，不能用独立游客入口或受控测试替代。当前可用 `/consult` 验证已有游客流程，继续执行课程审核与灰度门禁。官网未撤销的旧凭证不能通过增加助手校验频率识别。

单人投入，首批课程为 42、43、99。10 月底交付内部候选版与证据包；公开上线以全部准出通过为准。原有 17–25 人日粗估包含已完成任务，不能继续作为剩余工期，后续按实际模块和外部条件重新估算。

## 后续：版本适用范围与结构化事实联动

基础审核发布与撤回已实现，见[内部操作](../operations/L0_OPERATIONS.md)。下列更完整的资料治理目标仍待补齐，不能据此宣告生产准出。

1. 在已实现的显式原文继承和审核记录基础上，补齐适用人群、时间和版本范围，防止不同附件之间相互冲突；当前不声称每门课程仅有一份有效附件。
2. 已有候选发布事务和并发保护，继续完善范围变更、原文差异及生产备份恢复演练；上传和解析成功不得自动发布。
3. 对事实字段指定权威来源：价格、优惠、在售及购买入口来自官网业务接口；目录、基础、硬件、安排、证书和观看期限来自审核资料。采集快照作为候选证据，不自动覆盖已发布事实。
4. 冲突登记需保留原文及适用条件。结构化值在类型、单位和范围一致时可比较，自由文本差异进入人工复核，不声称完整语义冲突检测；未裁决字段停止确定性回答。
5. 继续补齐引用的片段定位及历史版本证据清单；当前已验证合格课程和发布状态检索、全部生成依赖撤回校验及历史重放门禁。
6. 内部管理页已有候选、审核记录、发布和撤回，后续增加原文差异及事实编辑。目前仅内部管理员执行审核发布；若需要独立审核员和发布员，应再定义角色和权限，不能自动代替课程方签收。

完成标准：不同内容更新可追溯；解析失败、并发发布和撤回竞争均不破坏有效版；旧片段不绕过事实冲突；撤回和在途输出有真实 PostgreSQL 回归；新迁移有升级与恢复方案。

## 课程资料与业务签收

核对仓库审核清单并整理三门课的来源、缺项和冲突；观看期限、42 的设备要求、购买页、顾问及备用联系人需真实证据。方向相关展示不能升级为个体适配结论。

由有权审核者签收事实与销售资格；课程方无法确认时保留待确认或不开放，不为测试改为通过。详见[内部运营](../operations/L0_OPERATIONS.md)和[试运行准出](../operations/PILOT_LAUNCH.md)。

## 官网恢复接入条件后

保留现有所有权和关联实现，补齐实际凭据传递、登录/退出/切号通知、旧凭证撤销保证、稳定客户 ID 及双测试账号。官网退出后旧凭证须被 `/miniapp/me` 拒绝，其他失败与封禁响应单独确认，不猜业务码。

完成标准：真实 A/B 隔离、当前咨询幂等关联、并发只归属一次、关联后旧游客失权、跨设备本人历史、在途退出与快速切号均签收。公开入口启用前完成代理/Cookie/CSP/SSE 验收；默认身份开关保持关闭，详见[对接问题](../integration/官网对接问题清单.md)。

## 部署、恢复与质量

隐私入口、发布前敏感规则扫描、历史复核留档及独立监控告警已实现；隔离虚构资料的数据库/文件还原、停用和危险降级保护演练通过。剩余：填写真实隐私信息并由负责人确认、复核七份历史资料、配置计费单价/预算和外部通知、在预发布验证真实快照及兼容镜像切换。详见[专项操作](../operations/PRIVACY_AND_SAFETY.md)。

- 实测同步入库对健康检查和咨询的影响，必要时移出事件循环，并限制并发、超时和队列长度。
- 明确生产资料存储。数据库保存元数据与引用，原文件需持久化及版本保留；对象存储供应方尚未确定，不把容器临时路径作为正式方案。
- 演练数据库与原文件联合恢复、镜像回滚、迁移兼容和关闭灰度；恢复后核对哈希、有效版本及核心问答。
- 以真实模型采样 1/5/10 并发，记录样本量、错误率、首个有效答案及整轮 p50/p95，不把进度事件当作答案。容量门槛根据证据和预算确认，首发保持单副本。
- 固定资料、模型、提示和代码版本，人工准确率至少 95%、任务完成率至少 90%、严重错误零；自动回归不能代替人工或真实环境签收。

具体步骤见[部署](../operations/DEPLOYMENT.md)和[验收](../operations/ACCEPTANCE.md)。未验证项明确列入证据包；官网客户范围未签收时，不能将游客候选版宣告为原完整首发已交付。

## 成熟知识库的限时验证

延续已定选择：MaxKB 优先，FastGPT 对照，累计最多 2 人日；尚未安装或采用。只验证正文解析、分片、检索、引用及管理收益，平台不成为第二套客户身份或历史主库。Dify 用作运行复盘参考，Chatwoot 仅在有实际坐席和值守需求时单独评估。

固定候选版本、镜像、许可、模型、资料和至少 20 个经过人工复核的对照案例，覆盖事实、多轮、未知、冲突、价格失败、提示注入、资格及旧资料撤回。单个候选安装排障最多半人日，总计达到 2 人日即收口，未验证项不得算通过，不自动追加其他平台。

只有实际 API 可用、许可条件解决、资格与版本隔离在检索前生效、撤回与严重错误场景全部通过、质量不低于同条件基线、可切回现有服务，且节省的维护人日超过接入和运维新增人日，才考虑局部采用。否则继续现有后端；不能只以安装成功或框架相近决定迁移。
