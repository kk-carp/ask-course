# 官网登录用户身份与历史归属契约

已确认：官网有普通登录账号，没有会员等级或付费会员身份。本文仅对接现有账号登录态，不要求新增会员系统或权益接口。

日期：2026-10-09。状态：所有者服务、当前咨询关联与 `/miniapp/me` 验证适配器已实现并通过受控测试；退出后旧凭证本次实测仍被官网接受，撤销未通过。官网暂时无法修改且未加载助手脚本，真实凭据传递、登录关联和跨设备签收暂缓，身份校验默认关闭。已核实的官网请求见[身份校验接口](官网身份校验接口.md)，剩余任务见[改进计划](../development/roadmap.md)。

## 新增官网接口说明对本契约的约束

官网侧接口和 CLI 原始说明单独保存在仓库外。下文仅保留与本项目身份边界相关的约束；外部说明不代表本项目联调结果，也不构成执行授权。

- 官网课程助手通过 `Authorization: Bearer <JWT 或 ts_ 凭证>` 接收登录身份，两种凭证绑定同一 `members.id`；个人工具身份由服务端注入，不接受工具参数 `user_id`。本项目拟以官网提供方与经服务端验证的 `members.id` 作为客户主体，仍需确认稳定性、账号删除/重建及环境命名空间。
- 官网原始资料没有列出独立客户验证接口；后续已取得 `/miniapp/me` 的 POST 格式与成功 ID 字段。不能把工具查询成功、`authenticated: true` 或客户端解码 JWT 当作身份验证，也不能把验证成功当作退出撤销已实现。
- CLI 的 AK/SK 属于密钥所属账号，`GET /miniapp/open/me` 是该调用账号的身份查询；现有说明未证明该接口接受终端客户 Bearer 凭证。不得用共享运营 AK/SK 识别每个访客，也不将 SK 放入官网组件。
- 外部 `GET /miniapp/ai/agent/tools` 与 `POST /miniapp/ai/agent/tools/{工具名}` 全部要求 JWT 或 `ts_`，即使 `search_courses` 查询公开课程也不例外。官网内置助手的游客能力不能推导为外部 Tool 可匿名调用。
- 官网内置助手的游客上下文为默认 120 分钟、登录历史写入 `business_agent` 来源；本项目游客 24 小时、登录用户 90 天及当前咨询关联规则继续按本契约实施。此次不接管官网 AI 历史，也不混用两套 `conversation_id`。

后续已取得 `/miniapp/me` 成功响应及 JWT 双头请求格式，并实现默认关闭的适配器；授权退出后校验仍返回成功，不能把撤销当作已确认。下一步需确认实际退出请求及服务端撤销，再完成双账号、跨设备与在途退出真实签收，剩余问题见[负责人清单](官网对接问题清单.md)。

## 身份边界

- 游客凭服务端签名 Cookie 访问本人未过期咨询。
- 官网登录用户由官网后端验证；适配器输出身份提供方、稳定外部用户 ID、验证有效期。上述字段由可信验证结果产生，禁止使用客户端 userId、昵称或角色作为授权。
- 内部管理员沿用内部登录；官网公共接口不继承其权限。登录用户知识检索仍受课程空间、销售审核范围和灰度控制。
- 校验失败、过期与接口暂不可用分别处理；不能失败后悄悄退回游客身份继续操作同一登录用户会话。

## 归属与保留

每段官网咨询属于一个游客或一个登录用户，不能同时授权给两类主体。登录用户身份由“提供方 + 外部用户 ID”共同区分，与内部 `users.id` 没有隐式对应关系。

沿用已确认范围：游客默认保留 24 小时，登录用户默认保留 90 天；按消息活动时间计算，读取、改名或身份关联不刷新消息活动时间。删除立即不可读、不可续问，随后定时物理清理。

项目负责人已确认：登录只关联当前选中、尚未过期且未删除的游客咨询；关联后游客 Cookie 不再拥有该会话，退出后也不能以游客身份读回。其他游客咨询不批量导入。不存在当前咨询时只建立登录用户身份，不创建空咨询或导入最近记录。

关联须原子且幂等：同一登录用户重复关联返回同一结果；另一个登录用户不得抢占。关联前确认签名游客 Cookie、当前会话归属、到期与删除状态；禁止只提交一个会话 ID 就认领。已实现的方案拒绝 15 分钟内存在有效问答认领的关联并返回 409；锁定并刷新后的所有者校验阻止原游客迟到回写。

## 已实现的接口边界

现有 `/widget/conversations` 继续服务客户，不调用内部 `/conversations` 恢复登录用户历史。客户历史服务统一接收已验证客户主体，业务层不能自行读取任意浏览器声明的用户 ID。

- `GET /widget/config`：返回经服务端解析的 `identity_kind` 和 `identity_key` 摘要，后者只作缓存分区，不能用于授权，不返回官网凭证。
- `POST /widget/conversations/{id}/associate`：在可信身份和原游客 Cookie 下原子关联指定咨询；请求体不能通过 accountId 指定所有者。
- 客户历史的新建、列表、消息、改名、删除与问答每次验证主体；按 ID 越权统一返回不可访问结果，不泄漏他人是否存在。

早期草案中的 `/widget/identity`、`/widget/identity/login` 和 `/widget/identity/logout` 未实现，不属于可调用协议。官网前端凭据传递尚未接入；助手视图清理不等于官网退出或令牌撤销，不提供公开模拟登录入口。

## 数据模型与迁移（已实现基础结构）

在现有官网咨询与消息记录上增加登录用户所有者，不把登录用户对话迁入内部账号会话表。保留原游客来源供受控关联审计，但不能继续用原游客 ID 授权已经归属登录用户的记录。

已实现 `WebsiteCustomer / website_customers`，保存本地 UUID、身份提供方 `provider`、官网稳定标识 `external_user_id` 和创建时间；前两项身份字段联合唯一且非空白，不保存令牌、密码或内部角色。实际 provider 命名与官网 ID 映射须由可信验证适配器确定。

现有咨询表增加 `customer_id`（外键，删除主体采用 RESTRICT）和 `source_visitor_id`（仅审计）。`visitor_id` 改为可空，数据库 `ck_consultation_one_owner` 强制游客所有者与客户所有者二选一；客户历史使用 `customer_id + last_activity_at + id` 索引。客户咨询不能以审计来源字段恢复游客权限。

Alembic `0003` 保留原游客记录、完整消息和活动时间，并回填来源游客标识。无客户数据时可降回 `0002`；出现客户主体或客户咨询后拒绝降级，避免丢失新所有权。SQLite 轻量回归与真实 PostgreSQL 的升级、唯一性、外键、排他约束和回滚保护均已有测试。清理区分游客 24 小时与客户默认 90 天（`CUSTOMER_CONSULTATION_DAYS`），读取和关联不得延长消息活动时间。

已实现 `WebsiteOwner` 统一主体与 `consultation_access` 授权查询：新建、分页、消息、改名、删除、结构化问诊与问答续写按同一所有者及其保留期校验；写操作获取行锁并刷新 ORM 记录，避免旧身份缓存绕过已提交的关联或删除。客户主体由经过验证的 `provider + external_user_id + valid_until` 建立，并发建立采用数据库冲突去重。内部管理员身份不参与上述授权，验证到期拒绝请求和最终回答落库。

`POST /widget/conversations/{conversation_id}/associate` 已接入关联事务，但依赖服务端可信身份验证结果和原签名游客 Cookie，不接受客户端账号 ID 授权。`verified_website_identity` 现已支持服务端 `/miniapp/me` 校验，`WEBSITE_IDENTITY_ENABLED` 默认关闭：关联时无身份返回 401，配置关闭时提交凭证返回 503，不自动降级为游客，不提供模拟登录。开启需先完成撤销与真实前端流程确认；客户路径测试覆盖依赖替换及受控 HTTP 上游，不使用真实凭证。

关联在单个事务中建立客户并锁定指定咨询；同一身份、同一来源游客重复关联返回同一结果，其他客户或游客一律不可认领。有效未完成的问答认领（15 分钟内）返回 409、提示完成后重试；超过 15 分钟的遗留认领随关联删除，原游客的迟到写入因所有者变化而拒绝。旧课程页问答没有持久认领，所有画像、课程绑定及最终历史写入均重新锁定校验归属；关联后旧请求拒绝写入和最终返回。读取、改名、关联和关联重试不刷新消息活动时间，事务失败恢复原归属；未指定当前咨询的内部服务调用只建立客户，不新建或批量关联咨询。

上游验证适配器已实现且默认关闭，撤销语义及官网实际登录回调仍待联调；本地请求执行期限不能代替官网凭证有效期或撤销机制。助手侧通知桥和旧视图清除已实现，详情见[身份事件接入](官网身份事件接入.md)，尚未连接官网实际事件。

## 前端行为

官网侧需在登录、退出与账号切换完成后通知助手，现有官网事件名称尚未确认。助手已提供 `ArborseekAgent.identityChanged()` 与 `arborseek:identity-changed` 通知桥：同步清空历史、当前会话引用、消息、草稿及弹层，取消在途请求，再向服务端复核身份、加载本人历史列表。旧请求的逐项与最终结果不能出现在新账号视图中，切号后的历史不会自动选中；复核失败保持关闭。

当前浏览器可存咨询 ID 作为定位，不可用它授权访问。跨设备登录后从服务端分页读取登录用户历史，不依赖上一设备 localStorage。不在 localStorage 保存登录用户令牌。

助手已支持同源跨标签通知和页面重新聚焦/可见时复核。官网未提供身份变化通知时，仍需每次在服务端验证；纯前端通知不能替代授权，前台页面发现撤销的实时性仍需官网事件或经确认的协议保证。

## 必须通过的验收场景

1. 游客 A 不能读取、改名、删除或续问游客 B 的咨询。
2. 内部管理员 Cookie 不增加官网咨询权限。
3. 登录用户 A 在两台设备登录后恢复同一本人历史，登录用户 B 不可访问。
4. 已验证登录用户 A 关联当前游客咨询成功；重复提交不重复创建主体或消息。
5. 其他游客咨询没有被隐式关联；伪造访客 Cookie 或只有会话 ID 时不能认领。
6. 已被登录用户 A 关联的咨询不能被登录用户 B 抢占；退出后原游客 Cookie 不可读。
7. 已过期或删除的咨询不能关联，也不能因迟到回答重新出现。
8. 登录、退出、账号切换后，旧历史与迟到流式事件不能显示到新主体。
9. 过期/撤销凭证拒绝登录用户历史与续问；验证上游故障返回可重试错误，不降级读取登录用户资料。
10. 登录用户读历史、改名与重复关联不延长保留期；清理按客户类型执行。
11. 灰度为 0、课程不合格时，登录用户也不能绕过公开准入或购买门禁。
12. PostgreSQL 下并发关联、重复请求及删除与回写竞争均符合上述归属和幂等规则。
