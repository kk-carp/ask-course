## 1. 目标与已确认范围

将售前助手接入官网全站：首页、列表页直接咨询，课程详情页自动携带页面课程。优先改善官网咨询界面；支持游客、官网登录用户身份识别和本人历史续聊；统一生产存储与课程事实管理。

已确认的产品选择：

- 非课程页直接输入目标或问题，不要求先选择课程。
- 桌面端右侧面板，移动端完整咨询页；不将内部演示页直接嵌入官网。
- 使用 Vue 3 + Vite + Ant Design Vue 4.2.6，与官网已核验的组件库版本对齐；主题色 `#1890ff`。官网只展示右下角“问问探界”入口及展开的问答面板，不增加课程展示首页。内部资料管理独立在 `/admin`，生产网关不对公众代理该入口。
- 左侧为对话历史，右侧为新会话与收起；历史采用浮层列表，展示对话主题短句，支持搜索、重命名和删除。手动名称不被自动主题覆盖。
- 登录后识别身份、关联本次咨询并恢复本人历史；暂不查询已购课程、订单和权益。
- 资料按字段指定权威来源，无法裁决的冲突交运营确认。
- 保留现有推荐、购买页引导和人工承接流程；不承担收款、退款执行、就业或项目完成保证。
- 内部管理页仅补资料审核、冲突处理所需功能，不做全面视觉改版。

- 默认收起、桌面浮层、移动端全屏、图标居中、蓝色主题；公开页面不再包含课程展示首页和内部管理。

- 官网通道固定为游客身份，内部管理员 Cookie 不改变官网授权。新增 `/widget/conversations` 客户接口，逐次校验签名 Cookie、归属、有效期和删除状态。
- `visitor_turns` 保存问题及完整回答快照，`history_json` 仅保留最近三轮供上下文理解。独立会话 ID、新建及提问幂等键、改名、删除、分页和刷新恢复已连接站点模式组件。轻量标题不增加模型调用。

- `ask_first_turn` 按是否已有完成消息判断站点首问；增加 `widget_history_read/write` 耗时。游客配置、历史、问答与购买响应使用 `Cache-Control: no-store`。

- 42、43、99 的仓库清单仍为 `recommendable`，完整销售审核未通过；公开入口保持关闭，需重新核验真实课程及联系人。

## 3. 全站入口与咨询界面

### 3.1 接入形式

独立部署 Agent，官网同源 `/agent/` 反向代理到服务，剥离前缀。全站改造完成后，在官网公共布局加载一次：

```html
<script defer src="/agent/widget.js" data-mode="site"></script>
```

`data-mode="site"` 已在本地实现；原 `data-course-id` 的课程页模式继续兼容。SPA 路由须显式调用 `ArborseekAgent.setPageContext({courseId})`，离开详情页传 `null`；浏览器前进后退同时监听 `popstate`。

代理覆盖组件、回答排版资源、配置、身份桥接和咨询接口；SSE 关闭缓冲与接口缓存，读取超时至少 180 秒。保留 Host、Origin、Cookie，正确传递 HTTPS 信息。匿名配置和身份相关响应不得被 CDN 共享缓存。官网 CSP 需允许同源脚本、接口、组件样式及实际使用的课程图片和顾问二维码。

官网实际网关、部署平台、路由框架尚不明确；由官网技术负责人确认后提供相应配置，不预设必须使用 Nginx。生产数据库和 Agent 管理入口不作为访客功能暴露。

### 3.2 页面与会话上下文

- 首页、列表页无课程上下文，直接进入目标理解和推荐。
- 详情页识别数字课程 ID。页面课程和用户已选咨询课程分别保存，用户明确选择优先；“当前页面这门课”指向页面课程。
- 官网普通页面跳转后恢复当前会话与最近消息。单页应用通过 `ArborseekAgent.setPageContext({courseId})` 更新上下文，非课程页传 `null`，组件不得重复挂载。
- 未审核课程页可提供全局选课，明确提示该页面课程暂未开放课程事实咨询；不把未审核课程作为已确认适配或购买依据。
- 全站灰度以“访客 + site”稳定分桶，课程页旧模式保持原分桶。全局入口至少要求一门课程通过现有完整门禁；具体课程事实与购买继续校验对应课程资格。

### 3.3 交互与视觉

- 与官网品牌一致；移除访客界面的内部账号登录、资料上传、接口字段和模型调试标签。
- 保留当前面板布局和历史浮层；补齐当前课程提示、服务端历史加载、到期提示及身份状态，不再重做公开首页。身份状态清晰但不阻塞游客使用。
- 历史短句采用用户问题的轻量主题提炼，无法归类时截取首问；手动名称优先。后续若引入模型摘要须异步生成，不能增加首问等待或覆盖手动名称。
- 推荐卡片展示推荐理由、适用条件、待确认项及详情入口；购买按钮继续受审核门禁控制。
- 多问题按提问顺序展示；区分查询中、部分完成、全部完成、失败和可重试状态，重试不重复插入同一轮历史。
- 资料来源默认折叠；重复标签合并；保留冲突和待核实提示。区分“采集于”“审核于”“生效于”，不把文件修改时间直接标为业务更新时间。
- 移动端适配软键盘和长消息，代码块、表格可横向滚动；键盘操作、焦点和关闭动作可用。
- 桌面和移动端设计预览已完成；后续对官网路由、软键盘、CSP、弹层层级及组件样式进行联调截图验收。组件库升级单独验证，避免随依赖升级改变弹层行为。

## 4. 游客与官网登录用户身份

### 4.1 信任边界

继续使用服务端签发的游客 Cookie。官网登录用户身份由官网后端验证，Agent 不读取官网密码，也不相信浏览器自行声明的用户 ID 或角色。

优先对接官网已有服务端登录校验；若现有身份不能直接验证，采用短期一次性交换码桥接：官网后端签发、Agent 后端兑换验证，再建立 Agent 客户会话。验证方式和外部接口地址是官网联调前置条件，不假定现有官网已经提供。

身份适配器统一输出身份提供方、稳定外部用户标识、验证有效期。显示昵称为可选字段，首期不收集手机号、邮箱或订单。官网登录用户与 Agent 内部管理员独立授权，禁止通过相同 ID、昵称或前端角色字段继承管理权限。

### 4.2 续聊与隔离

- 客户会话统一支持游客所有者和登录用户所有者，画像、消息和课程上下文沿用同一业务流程；不将官网登录用户直接接入内部管理员登录问答分支。
- 登录后验证当前游客 Cookie 与会话归属，将当前咨询原子关联到已验证登录用户；操作幂等，不自动合并该浏览器所有旧游客记录。
- 登录用户跨页或换设备登录后，只能恢复本人仍在保留期内的历史。
- 退出或切换账号时清空已渲染的登录用户历史和本地会话引用，更新身份绑定并重新加载可访问历史。每次历史读取与问答均在服务端检查所有权。
- 官网需通知登录、退出及账号切换；后端验证过期或无法确认时不能继续读取登录用户历史。游客咨询可继续，但须显式切换到独立游客会话。
- 浏览器会话 ID 只用于定位，不是授权凭证；不在 localStorage 中保存登录用户令牌或完整身份资料。
- 现存游客最近三轮可在迁移时保留，未保存的历史不得声称已经恢复。

## 5. 生产存储与迁移

### 5.1 存储分工

- PostgreSQL + pgvector：会话、消息、身份关联、画像、课程事实、资料元数据与版本、审核记录、冲突记录、向量、联系人、灰度和事件。
- 文件存储：原始文档、官网采集快照及版本文件。预发布可使用持久磁盘；公开生产采用对象存储，数据库保存对象引用与内容哈希，不依赖容器内临时路径。
- 进程内状态仅用于可丢失缓存；首期单副本可保留现有限流和耗时统计，多副本前迁移到共享限流及统一指标。
- 业务规则代码继续版本管理；审核资料、发布状态和有效事实以数据库为运行时唯一来源。JSON 作为迁移、导入导出和回滚快照，不与数据库并行作为独立可修改主数据源。

### 5.2 迁移与保留

- 引入版本化数据库迁移，先在副本导入现有课程事实、审核配置、快照和会话；保留原始来源及状态，不自动把旧 `provided` 标记提升为人工审核通过。
- 上传原始文件至对象存储，核对内容哈希、对象可读性、课程 ID 与向量对应关系；切换后保留旧版本恢复路径。
- 会话、消息和画像按所属主体删除：默认游客 24 小时、登录用户 90 天，漏斗事件 30 天；游客 Cookie 可保留 30 天用于稳定识别，不等于对话保留 30 天。
- 当前游客清理每 5 分钟执行，不能只在启动时清理；到期会话立即不可访问，物理删除由清理任务完成。资料版本独立保留，不能跟随会话清理删除。
- 数据库每日备份，保留至少最近 7 天和每次发布前备份；对象文件开启版本保留。切换、删除和回滚均需同时考虑数据库引用与对象版本。
- 预发布演练数据库与文件联合恢复、应用镜像回滚；记录恢复结果。破坏性迁移单独设计恢复步骤，不以镜像回退代替数据恢复。

## 6. 权威来源、冲突与发布

### 6.1 字段规则

- 价格、活动、在售状态、购买入口：以指定官网业务接口的可核实字段为准。价格现有缓存最多一分钟；缓存过期且接口失败，不用旧文档或模型猜测替代。下单金额以官网订单页面为准。
- 目录、基础、硬件、授课安排、证书、观看期限：以课程负责人审核发布的当前有效事实版本为准。
- 抓取的页面文字和宣传快照：作为候选证据与变更线索，未经审核不覆盖已发布事实，也不自动成为可检索的权威课程资料。
- 权威字段有明确定义且适用范围相同，可继续按权威值回答，同时登记其他来源偏差；接口内部矛盾、多个有效审核版本矛盾或适用条件不明时，暂停该字段的确定回答。
- 确定冲突时回答“资料存在不一致，需要课程顾问确认”；其他无冲突项目照常回答。结构化事实不能通过绕回知识库生成而规避冲突状态。

### 6.2 事实与资料生命周期

每条事实关联课程 ID、字段、值与适用条件、来源版本、采集时间、业务生效时间、审核人和审核时间；区分草稿、已发布、待核实、冲突和失效。每个课程字段与适用范围只允许一个当前有效发布版本。

内容入库先保存候选版本，再抽取结构化事实并比较。只有类型、课程、适用范围和单位一致的结构化值可自动比较；自由文本差异只进入人工检查，不能声称已实现完整语义冲突检测。

最低运营流程为：导入或采集 → 差异与冲突记录 → 课程负责人确认 → 原子发布有效版本 → 更新检索可见版本并失效缓存。若更换了事实版本，旧矛盾片段必须退出当前回答依据；不能仅修改事实表却让旧正文继续参与检索。

例如：文档写“购买后一年”，官网宣传写“长期有效”。若未确认两者是否分别指课程权限和下载资料，则暂停观看期限承诺；负责人确认适用范围后再发布，不由模型选择看起来更新的说法。

内部管理页仅补版本查看、待处理冲突列表、原文证据、审核发布和撤回入口。冲突登记去重，重复采集不重复生成同一问题；更新一个字段不要求整门课程全部停止咨询。

## 7. 下一步改进方案与实施顺序

### 7.1 本轮实现：全站游客接入 + 服务端历史闭环

先在本地和预发布实现游客主链路，不以开放正式官网为交付条件。沿用当前 Vue 界面，不增加登录用户订单、支付执行、通用知识库或新的课程展示页面。

按以下顺序推进：

1. **全站协议与准入**：`/widget/config` 增加站点模式及可选课程 ID；`site_widget` 支持无课程提问，事件允许站点级上下文。首次配置签发访客 Cookie，后续问答、历史和事件使用同一身份。站点灰度与课程资格分别检查；官网通道按客户身份解析，不继承内部管理员权限。保留 `course_page` 兼容路径。
2. **会话与消息持久化**：完成必要的版本化迁移，将完整消息记录与模型最近三轮上下文分离；增加标题、手动命名标记、消息活动时间、到期和删除状态。显式创建新会话，不再通过清空 ID 隐式复用最近记录。新建和消息提交使用请求幂等键，断线重试不重复创建会话或保存同一轮。
3. **客户历史接口**：实现仅当前访客可读写的列表、消息、改名和删除接口；分页且有界加载，正文不进知识库。默认游客保留 24 小时，读取和改名不延长有效期；定时清理不依赖启动。删除立即不可读、不可续问，随后清理消息和画像；流式响应晚到不能恢复已删除记录。
4. **前端接入真实历史**：刷新后恢复所选有效会话；改名失败保留原名称并提示，删除失败不能假装成功。删除当前会话回到新会话；到期或删除后提示重新咨询，不把新问题静默追加到其他旧会话。历史课程卡片不作为当前售价或购买资格证明，购买仍须实时校验。
5. **全站挂载与跨页上下文**：实现 `data-mode="site"` 和 `ArborseekAgent.setPageContext({courseId})`；官网路由钩子更新页面课程，页面课程与当前咨询课程分别传递。普通导航通过服务端恢复历史；单页路由只挂载一次，返回首页清除页面课程。切页或切会话后的迟到结果只能归入原请求会话，不能覆盖新会话。

本地已实现协议（请求示例及迁移步骤见[游客全站接入](游客全站接入.md)）：

- `GET /widget/config?mode=site`：站点配置，可携带可选课程上下文。
- `POST /ask/stream`：沿用 SSE 事件，`channel=site_widget` 允许空课程；传递会话、页面课程与幂等请求标识。
- `POST /widget/conversations`：显式新建客户会话，与现有结构化问诊 `/consultations` 分开。
- `GET /widget/conversations`、`GET /widget/conversations/{id}/messages`：分页读取本人有效历史。
- `PATCH /widget/conversations/{id}`：更新短标题，限制长度、去除首尾空白，记录手动名称。
- `DELETE /widget/conversations/{id}`：删除本人会话，重复请求不恢复记录。

以上为客户命名空间，不能通过内部 `/conversations` 绕过客户授权。所有按 ID 的操作检查访客归属、有效期和删除状态；伪造访客 ID、他人的会话 ID、缺失 Cookie 均不能读写他人记录。

本阶段验收必须同时满足：

- 首页不选课即可问“推荐适合零基础的课程”，详情页可以问当前课程；没有合格课程或灰度为 0 时不开放入口。
- 新会话获得不同服务端 ID；同访客连续创建两次不串上下文；相同幂等请求只创建或保存一次。
- 刷新、普通跨页、单页路由跳转后能恢复有效对话；页面课程、所选课程和原会话消息不串用。
- 历史列表、主题短句、改名、删除均以服务端结果为准；改名刷新后仍在，删除刷新后不再出现，过期后无法续问。
- 两个独立访客互不可见，内部管理员登录不改变官网权限；失败重试与迟到流式事件不制造重复或复活删除数据。
- 保留首问、三问与五问的耗时指标，新增历史读写耗时；显式创建会话后首问会携带 ID，需按会话是否已有消息识别首问，不能继续仅用请求是否携带 ID 判定。实测无额外同步摘要模型调用。接口示例、迁移、回归测试与前端联调同步交付。

### 7.2 后续阶段与公开发布依赖

1. **生产存储与事实治理**：完成文件存储、审核版本、冲突处理、缓存失效与旧片段过滤；在副本核验导入与联合恢复。下一阶段必要的会话迁移提前实施；完整资料治理不阻塞本地游客开发，但仍是公开上线前置条件。
2. **官网登录用户续聊**：完成服务端身份验证、当前游客咨询关联、登录用户历史、登录退出与账号切换隔离；复用客户历史领域接口，不将登录用户当作内部用户。
3. **同源预发布联调与公开灰度**：确认代理、SSE、Cookie、CSP、审核门禁、真实课程数据、容量和回滚。默认整体首发包含登录用户续聊；如官网身份接口延期，可单独验收游客版，但需明确登录用户能力尚未交付，并完成游客版全部公开准出条件。

官网对接确认同步进行：网关与部署位置、路由钩子、身份校验接口、样式和 CSP 约束、课程负责人及审核数据。未确认的外部事项不阻止本地实现，但本地预览通过不能替代官网预发布联调。

官网技术团队负责网关、全站脚本与路由接入、身份验证接口和测试账号；Agent 团队负责组件、服务、数据迁移、身份适配、事实治理和指标；课程负责人负责资料、字段权威性、冲突裁决及联系人核验。

游客协议已实现；随后增加登录用户身份建立与失效、内部资料版本与审核接口。后续能力尚未实现，联调时持续维护契约并保持课程页协议兼容。

## 8. 验收、监控与回滚

- 界面：首页、列表、详情页加载一次，移动端软键盘不遮挡输入；Markdown、表格、长回答、来源折叠及去重正常；失败可重试。
- 对话：首页直接推荐、详情页事实问答、跨页续聊、切换课程、三问与五问、混合转人工完整；当前页面和已选课程不串课。新会话必须创建新服务端记录，历史重命名、删除和到期行为跨刷新一致。
- 身份：游客登录关联仅本次咨询；登录用户跨设备恢复本人历史；退出、账号切换、过期凭证、伪造 ID、跨访客或跨登录用户会话访问均正确隔离。
- 资料：权威接口更新、抓取与审核内容冲突、同字段多版本、未知适用条件、接口失败、发布撤回、旧片段排除、缓存失效均有回归；运营人工核对真实事实与来源。
- 存储：容器重建不丢资料，迁移数量与哈希一致，到期不可读、定时清理和联合备份恢复通过。
- 性能：预发布测实际模型 1、5、10 并发；分别记录首次与后续咨询、三问与五问的第一项答案及全部完成耗时。使用 `ask_first_turn`、`ask_catalog`、`ask_understanding`、`ask_questions`、`ask_turn` 定位，不将受控模拟提速视为线上指标。
- 发布前基于实测确定容量与延迟门槛，再执行 5% → 25% → 100%；每阶段至少观察 7 天。错误课程、错误顾问、越权会话、错误购买入口和严重事实错误为零才扩大。
- 灰度设置 0 后阻断后续官网咨询与购买跳转；已打开组件在再次请求时提示暂停并收起入口，不声称已经发出的答案会被撤回。官网保留撤下脚本作为第二道回滚，应用和资料版本可分别恢复。

尚待官网确认的外部信息：实际部署平台与代理能力、路由生命周期、品牌规范、身份验证方式与接口、稳定用户标识、登录退出通知机制、可用文件存储、课程资料负责人。以上未确认前可以推进本地改造，但不能宣称官网登录用户和生产接入已完成。
