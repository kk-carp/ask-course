# 官网全站接入实施计划

更新日期：2026-10-08。状态：前端 Vue 组件已完成本地改造；全站接口、身份桥接、存储治理及生产接入待实施。

[文档导航](../README.md) · [当前实现](../architecture/current-system.md) · [现有课程页准出](../operations/PILOT_LAUNCH.md)

## 1. 目标与已确认范围

将售前助手接入官网全站：首页、列表页直接咨询，课程详情页自动携带页面课程。优先改善官网咨询界面；支持游客、官网会员身份识别和本人历史续聊；统一生产存储与课程事实管理。

已确认的产品选择：

- 非课程页直接输入目标或问题，不要求先选择课程。
- 桌面端右侧面板，移动端完整咨询页；不将内部演示页直接嵌入官网。
- 使用 Vue 3 + Vite；官网只展示右下角“问问探界”入口及展开的问答面板，不增加课程展示首页。内部资料管理独立在 `/admin`。
- 登录后识别身份、关联本次咨询并恢复本人历史；暂不查询已购课程、订单和权益。
- 资料按字段指定权威来源，无法裁决的冲突交运营确认。
- 保留现有推荐、购买页引导和人工承接流程；不承担收款、退款执行、就业或项目完成保证。
- 内部管理页仅补资料审核、冲突处理所需功能，不做全面视觉改版。

## 2. 当前基础与待补能力

现有代码已有独立服务、PostgreSQL + pgvector、签名游客 Cookie、最近对话保存、课程页组件、SSE 多问题事件、课程白名单和灰度开关。响应提速、Markdown 渲染和重复来源标签修复已推送。

仍需补齐：

- 组件目前只在 `/course/{id}` 且脚本课程 ID 匹配时加载；首页、列表页不能直接复用。
- `site_widget` 请求目前仍要求课程 ID，需要支持无课程的全站咨询。
- Agent 内部登录不等于官网会员登录，尚无官网身份校验与游客转会员关联。
- 游客历史目前只保留最近三轮；浏览器只保存会话 ID，尚无完整历史恢复界面。
- 课程事实、审核清单和官网快照分散在文件中，尚无统一版本发布、失效和冲突审核流程。
- 当前冲突处理只有少量特定规则，固定取用顺序不能证明来源之间不存在冲突。
- 42、43、99 的仓库清单仍为 `recommendable`，完整销售审核未通过；公开入口需要按部署环境重新核验门禁。

## 3. 全站入口与咨询界面

### 3.1 接入形式

独立部署 Agent，官网同源 `/agent/` 反向代理到服务，剥离前缀。全站改造完成后，在官网公共布局加载一次：

```html
<script defer src="/agent/widget.js" data-mode="site"></script>
```

上述 `data-mode="site"` 为待实现能力。原 `data-course-id` 的课程页模式继续兼容。

代理覆盖组件、回答排版资源、配置、身份桥接和咨询接口；SSE 关闭缓冲与接口缓存，读取超时至少 180 秒。保留 Host、Origin、Cookie，正确传递 HTTPS 信息。匿名配置和身份相关响应不得被 CDN 共享缓存。官网 CSP 需允许同源脚本、接口、组件样式及实际使用的课程图片和顾问二维码。

官网实际网关、部署平台、路由框架尚不明确；由官网技术负责人确认后提供相应配置，不预设必须使用 Nginx。生产数据库和 Agent 管理入口不作为访客功能暴露。

### 3.2 页面与会话上下文

- 首页、列表页无课程上下文，直接进入目标理解和推荐。
- 详情页识别数字课程 ID。页面课程和用户已选咨询课程分别保存，用户明确选择优先；“当前页面这门课”指向页面课程。
- 官网普通页面跳转后恢复当前会话与最近消息。单页应用通过 `ArborseekAgent.setPageContext({courseId})` 更新上下文，非课程页传 `null`，组件不得重复挂载。
- 未审核课程页可提供全局选课，明确提示该页面课程暂未开放课程事实咨询；不把未审核课程作为已确认适配或购买依据。
- 全站灰度以“访客 + site”稳定分桶，课程页旧模式保持原分桶。全局入口至少要求一门课程通过现有完整门禁；具体课程事实与购买继续校验对应课程资格。

### 3.3 交互与视觉

- 与官网品牌一致；移除访客界面的内部账号登录、资料上传、接口字段和模型调试标签。
- 面板包含当前咨询课程、消息区、输入区、新咨询、历史咨询和联系顾问入口；身份状态清晰但不阻塞游客使用。
- 推荐卡片展示推荐理由、适用条件、待确认项及详情入口；购买按钮继续受审核门禁控制。
- 多问题按提问顺序展示；区分查询中、部分完成、全部完成、失败和可重试状态，重试不重复插入同一轮历史。
- 资料来源默认折叠；重复标签合并；保留冲突和待核实提示。区分“采集于”“审核于”“生效于”，不把文件修改时间直接标为业务更新时间。
- 移动端适配软键盘和长消息，代码块、表格可横向滚动；键盘操作、焦点和关闭动作可用。
- 先完成桌面与移动端设计预览，再实现并截图核验。品牌色、字体与官网现有规范对齐。

## 4. 游客与官网会员身份

### 4.1 信任边界

继续使用服务端签发的游客 Cookie。官网会员身份由官网后端验证，Agent 不读取官网密码，也不相信浏览器自行声明的用户 ID 或角色。

优先对接官网已有服务端登录校验；若现有身份不能直接验证，采用短期一次性交换码桥接：官网后端签发、Agent 后端兑换验证，再建立 Agent 客户会话。验证方式和外部接口地址是官网联调前置条件，不假定现有官网已经提供。

身份适配器统一输出身份提供方、稳定外部用户标识、验证有效期。显示昵称为可选字段，首期不收集手机号、邮箱或订单。官网会员与 Agent 内部管理员独立授权，禁止通过相同 ID、昵称或前端角色字段继承管理权限。

### 4.2 续聊与隔离

- 客户会话统一支持游客所有者和会员所有者，画像、消息和课程上下文沿用同一业务流程；不将官网会员直接接入内部管理员登录问答分支。
- 登录后验证当前游客 Cookie 与会话归属，将当前咨询原子关联到已验证会员；操作幂等，不自动合并该浏览器所有旧游客记录。
- 会员跨页或换设备登录后，只能恢复本人仍在保留期内的历史。
- 退出或切换账号时清空已渲染的会员历史和本地会话引用，更新身份绑定并重新加载可访问历史。每次历史读取与问答均在服务端检查所有权。
- 官网需通知登录、退出及账号切换；后端验证过期或无法确认时不能继续读取会员历史。游客咨询可继续，但须显式切换到独立游客会话。
- 浏览器会话 ID 只用于定位，不是授权凭证；不在 localStorage 中保存会员令牌或完整身份资料。
- 现存游客最近三轮可在迁移时保留，未保存的历史不得声称已经恢复。

## 5. 生产存储与迁移

### 5.1 存储分工

- PostgreSQL + pgvector：会话、消息、身份关联、画像、课程事实、资料元数据与版本、审核记录、冲突记录、向量、联系人、灰度和事件。
- 文件存储：原始文档、官网采集快照及版本文件。预发布可使用持久磁盘；公开生产采用对象存储，数据库保存对象引用与内容哈希，不依赖容器内临时路径。
- 进程内状态仅用于可丢失缓存；首期单副本可保留现有限流和耗时统计，多副本前迁移到共享限流及统一指标。
- 业务规则代码继续版本管理；审核资料、发布状态和有效事实以数据库为运行时唯一来源。JSON 作为迁移、导入导出和回滚快照，不与数据库并行作为独立可修改主数据源。

### 5.2 迁移与保留

- 引入版本化数据库迁移，先在副本导入现有课程事实、审核配置、快照和会话；保留原始来源及状态，不自动把旧 `provided` 标记提升为人工审核通过。
- 上传原始文件至对象存储，核对内容哈希、对象可读性、课程 ID 与向量对应关系；切换后保留旧版本恢复路径。
- 会话、消息和画像按所属主体删除：默认游客 24 小时、会员 90 天，漏斗事件 30 天；游客 Cookie 可保留 30 天用于稳定识别，不等于对话保留 30 天。
- 定时清理每日执行，不能只在启动时清理；到期会话立即不可访问，物理删除由清理任务完成。资料版本独立保留，不能跟随会话清理删除。
- 数据库每日备份，保留至少最近 7 天和每次发布前备份；对象文件开启版本保留。切换、删除和回滚均需同时考虑数据库引用与对象版本。
- 预发布演练数据库与文件联合恢复、应用镜像回滚；记录恢复结果。破坏性迁移单独设计恢复步骤，不以镜像回退代替数据恢复。

## 6. 权威来源、冲突与发布

### 6.1 字段规则

- 价格、活动、在售状态、购买入口：以指定官网业务接口的可核实字段为准。价格现有缓存最多一分钟；缓存过期且接口失败，不用旧文档或模型猜测替代。下单金额以官网订单页面为准。
- 目录、基础、硬件、授课安排、证书、观看期限：以课程负责人审核发布的当前有效事实版本为准。
- 抓取的页面文字和宣传快照：作为候选证据与变更线索，未经审核不覆盖已发布事实，也不自动成为可检索的权威课程资料。
- 权威字段有明确定义且适用范围相同，可继续按权威值回答，同时登记其他来源偏差；接口内部矛盾、多个有效审核版本矛盾或适用条件不明时，暂停该字段的确定回答。
- 确定冲突时回答“资料存在不一致，需要课程顾问确认”；其他无冲突项目照常回答。结构化事实不能通过绕回知识库生成而规避冲突状态。

### 6.2 事实与资料生命周期

每条事实关联课程 ID、字段、值与适用条件、来源版本、采集时间、业务生效时间、审核人和审核时间；区分草稿、已发布、待核实、冲突和失效。每个课程字段与适用范围只允许一个当前有效发布版本。

内容入库先保存候选版本，再抽取结构化事实并比较。只有类型、课程、适用范围和单位一致的结构化值可自动比较；自由文本差异只进入人工检查，不能声称已实现完整语义冲突检测。

最低运营流程为：导入或采集 → 差异与冲突记录 → 课程负责人确认 → 原子发布有效版本 → 更新检索可见版本并失效缓存。若更换了事实版本，旧矛盾片段必须退出当前回答依据；不能仅修改事实表却让旧正文继续参与检索。

例如：文档写“购买后一年”，官网宣传写“长期有效”。若未确认两者是否分别指课程权限和下载资料，则暂停观看期限承诺；负责人确认适用范围后再发布，不由模型选择看起来更新的说法。

内部管理页仅补版本查看、待处理冲突列表、原文证据、审核发布和撤回入口。冲突登记去重，重复采集不重复生成同一问题；更新一个字段不要求整门课程全部停止咨询。

## 7. 实施顺序与交付

1. **官网对接确认与设计预览**：确认网关、部署位置、路由、身份校验接口、品牌规范及课程负责人；产出桌面与移动端预览，冻结身份适配边界和权威字段清单。
2. **存储与事实治理**：完成版本迁移、生产文件存储、资料审核发布、冲突处理、缓存失效与旧片段过滤；在副本核验导入与恢复。
3. **全站游客咨询与界面升级**：支持无课程配置和提问、上下文切换、最近历史恢复、移动端布局及全站灰度；继承已修复的排版与响应性能行为。
4. **官网会员续聊**：完成服务端身份验证、当前游客咨询关联、会员历史、登录退出与账号切换隔离。
5. **同源预发布联调与公开灰度**：确认代理、SSE、Cookie、CSP、审核门禁、真实课程数据、容量和回滚。默认整体首发包含会员续聊；如官网身份接口延期，可单独验收游客版，但需明确标注会员能力尚未交付。

官网技术团队负责网关、全站脚本与路由接入、身份验证接口和测试账号；Agent 团队负责组件、服务、数据迁移、身份适配、事实治理和指标；课程负责人负责资料、字段权威性、冲突裁决及联系人核验。

接口增量包括：`/widget/config` 全站模式与可选课程上下文；`site_widget` 无课程问答；客户身份建立与失效；仅本人可读的客户历史；内部资料版本与审核接口。全部为待实现能力，联调时更新接口示例并保持原课程页协议兼容。

## 8. 验收、监控与回滚

- 界面：首页、列表、详情页加载一次，移动端软键盘不遮挡输入；Markdown、表格、长回答、来源折叠及去重正常；失败可重试。
- 对话：首页直接推荐、详情页事实问答、跨页续聊、切换课程、三问与五问、混合转人工完整；当前页面和已选课程不串课。
- 身份：游客登录关联仅本次咨询；会员跨设备恢复本人历史；退出、账号切换、过期凭证、伪造 ID、跨访客或跨会员会话访问均正确隔离。
- 资料：权威接口更新、抓取与审核内容冲突、同字段多版本、未知适用条件、接口失败、发布撤回、旧片段排除、缓存失效均有回归；运营人工核对真实事实与来源。
- 存储：容器重建不丢资料，迁移数量与哈希一致，到期不可读、定时清理和联合备份恢复通过。
- 性能：预发布测实际模型 1、5、10 并发；分别记录首次与后续咨询、三问与五问的第一项答案及全部完成耗时。使用 `ask_first_turn`、`ask_catalog`、`ask_understanding`、`ask_questions`、`ask_turn` 定位，不将受控模拟提速视为线上指标。
- 发布前基于实测确定容量与延迟门槛，再执行 5% → 25% → 100%；每阶段至少观察 7 天。错误课程、错误顾问、越权会话、错误购买入口和严重事实错误为零才扩大。
- 灰度设置 0 后阻断后续官网咨询与购买跳转；已打开组件在再次请求时提示暂停并收起入口，不声称已经发出的答案会被撤回。官网保留撤下脚本作为第二道回滚，应用和资料版本可分别恢复。

尚待官网确认的外部信息：实际部署平台与代理能力、路由生命周期、品牌规范、身份验证方式与接口、稳定用户标识、登录退出通知机制、可用文件存储、课程资料负责人。以上未确认前可以推进本地改造，但不能宣称官网会员和生产接入已完成。
