# 游客全站接入与验证

当前实现随本次提交推送，尚未发布官网；官网会员身份尚未接入。技术栈沿用 Vue、Ant Design Vue、FastAPI、PostgreSQL；新增 Alembic 已由用户确认。

## 迁移与启动

安装最新 requirements；对已有数据库先做完整备份并验证可恢复，再在项目根目录执行：

```powershell
python -m alembic upgrade head
python -m alembic current
npm run build --prefix frontend
uvicorn backend.main:app --reload --reload-dir backend
```

版本应为 `0003 (head)`。`0001` 接管旧表，`0002` 新增会话标题、手动命名、活动时间、删除状态和完整问答表，`0003` 新增客户主体和所有者约束并保留旧游客归属；旧上下文保留，不虚构旧完整消息。启动检查版本，未迁移会明确失败。发布时先停旧版本写入、备份、迁移再启动新版本；不能让旧代码的自动建表与迁移并发运行。

Docker 首次运行先启动 PostgreSQL，再用同一镜像、环境文件执行 `docker compose run --rm --no-deps api python -m alembic upgrade head`，最后启动 API。迁移脚本包含在镜像内，命令行迁移通过 PostgreSQL advisory lock 串行执行。

`0002` 的 downgrade 会删除新增历史及相关字段，仅适用于有恢复方案的回退演练；应用镜像回退不能自动恢复这些数据。`0001` 不提供删除既有业务表的回退。迁移方式遵循 [Alembic 官方迁移环境说明](https://alembic.sqlalchemy.org/en/latest/tutorial.html)。

## 官网脚本

### 官网暂时无法改动：独立游客页面

2026-10-09 用户确认官网暂时无法修改，且尚未加载本项目助手脚本。目前先使用助手服务自身的 `/consult`，无需改官网或安装浏览器扩展。构建并启动后，本地可访问 `http://127.0.0.1:8000/consult`；后续独立部署需使用助手服务自己的 HTTPS 地址。当前未部署此入口。

该页面使用 `data-mode="site"`，请求真实 `/widget/config?mode=site`，复用签名游客 Cookie、服务端 24 小时历史、幂等和权限校验。审核、灰度或联系人条件未满足时入口保持关闭；不能将内部预览 `/`、`/qa`、`/login` 的可见面板作为生产门禁通过的证明。构建产物缺失时 `/consult` 返回 503，要求重新构建。

保留 `WEBSITE_IDENTITY_ENABLED=false`。独立页面不读取、复制或保存官网凭证，不与官网会员自动关联，也不提供会员跨设备历史。官网退出或切号不会清除助手游客记录；共享浏览器应按需删除助手中的咨询。助手自身的历史删除与 24 小时过期规则继续生效，内部管理账号不能替代官网客户身份。

官网后续可改动时，再接入下述脚本、可信凭据传递、撤销及身份变化通知，并验证双账号隔离和当前游客咨询关联。详情见[身份事件接入](官网身份事件接入.md)。

### 官网具备接入条件后

官网公共布局加载一次；同源 `/agent/` 代理到服务并剥离前缀。不要把内部预览首页嵌入官网。

```html
<script defer src="/agent/widget.js" data-mode="site"></script>
```

SPA 在路由完成后更新上下文；非课程页传 `null`，普通全页跳转会自动读取路径并恢复当前会话。

```javascript
window.ArborseekAgent?.setPageContext({courseId: '43'});
window.ArborseekAgent?.setPageContext({courseId: null});
```

首次脚本配置签发签名游客 Cookie；后续请求携带同一 Cookie。配置响应 `enabled=false` 时不展示入口。站点门禁至少要求一门白名单课程完整审核、正文 ready 且联系人可用；灰度使用访客级站点分桶。课程推荐、事实查询及正文检索均限定在合格课程，未选择合格课程时不能检索整个课程库。购买仍独立复核。

当前仓库课程审核仍未满足正式开放条件，不能为了看到入口绕过门禁。已有 `/course/{id}` 加 `data-course-id` 的旧嵌入模式继续兼容；本地首页 `data-preview=true` 保持内部调试与内存历史，不代表站点模式验收。

## 请求契约

以下路径是服务内部路径，官网代理前加 `/agent`。问答、历史、配置、购买响应均 `no-store`；代理不得缓冲 SSE 或共享缓存 Cookie 响应。

1. `GET /widget/config?mode=site`，可带 `course_id`；返回 `enabled`、`history_enabled`、`history_hours` 及合格页面课程。
2. `POST /widget/conversations`，JSON `{"request_id":"UUID"}`；返回 `id`、`title` 等。相同新建编号幂等，不复用“最近一场”。前端在新会话第一次发问时创建，空白新会话无需提前占用存储。
3. `POST /ask/stream`，JSON 示例：

```json
{
  "question": "零基础适合什么课程？",
  "channel": "site_widget",
  "course_id": null,
  "conversation_id": "服务端会话 UUID",
  "request_id": "本轮 UUID"
}
```

`course_id` 是页面上下文，明确选定的咨询课程另存画像。服务端忽略不合格页面课程。`request_id` 在本轮重试时复用；同编号不同问题返回 409，处理中返回 409，完成后重放最终回答，不再调用模型。临时上游错误不缓存为成功回答。进程中断造成的处理中记录在 15 分钟后可重新认领；不同认领的迟到结果不能覆盖新结果。

4. `GET /widget/conversations?offset=0&limit=30`；`GET /widget/conversations/{id}/messages?offset=0&limit=50`。返回 `items`、`next_offset`（结束为 null）；limit 最大 100。消息按轮保存问题和完整回答快照，包括来源和课程卡片。恢复历史不重新查询模型。
5. `PATCH /widget/conversations/{id}`，JSON `{"title":"我的选课计划"}`；标题 1–40 字，去首尾空白，手动标题不被自动主题覆盖。
6. `DELETE /widget/conversations/{id}`；204，立即失效，重复删除幂等。所有按 ID 的读取和写入均校验本人归属；知道会话 ID 不能绕过授权。

游客默认保留 24 小时，以消息活动时间为准；读取与改名不延期。删除和过期会话立即不可访问，每 5 分钟清理完整消息、画像及会话。浏览器仅保存所选会话 ID，全文由服务端恢复。清 Cookie 或换浏览器不恢复原游客身份。历史卡片记录当时回答，点击购买仍重新校验当前审核状态和地址。

## 自动验证与联调提问

```powershell
python -m pytest -q
npm run build --prefix frontend
npm test --prefix frontend
node --test tests/frontend_answer.test.cjs
```

测试覆盖独立游客隔离、改名不延期、重复请求重放、临时失败重试、删除后迟到结果、迁移与回退、全站挂载、刷新恢复、真实 HTTP 契约和 SPA 上下文。独立 PostgreSQL 测试库另行演练过升级、回退、再升级与旧数据保留；不代表官网真实数据审核通过。

预发布准备好合格课程后按顺序验证：

- 首页：“我没有机器人基础，每周能学 5 小时，想先了解适合的入门课程。”
- 详情页：“当前页面这门课需要什么基础？需要买硬件吗？课程目录是什么？”
- 继续：“刚才推荐的第一门课适合没有硬件的人吗？”；跳转非课程页再追问，确认没有改变所选咨询课程。
- 刷新，确认消息与卡片恢复；改名后再次刷新，确认名称保留。
- 新建第二场咨询，确认旧画像没有串入；删除当前场后刷新，确认不再出现。
- 两个独立浏览器交叉请求会话 ID，均不能读取或改名；内部管理员登录后，官网请求仍为游客范围。
- 关闭灰度或撤销课程资格，确认新请求被拒绝；不能仅隐藏前端按钮。

`ask_first_turn` 对站点请求按“是否已有完成消息”统计，已建空会话仍算首问；`widget_history_read/write` 提供历史接口耗时。真实首问、三问、五问延迟仍需在预发布环境采样。
