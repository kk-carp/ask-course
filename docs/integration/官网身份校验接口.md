# 官网客户身份校验适配器

日期：2026-10-13。状态：本地官网与 PHP 已完成密码登录、身份透传、当前游客咨询关联、刷新历史、双账号隔离和在途退出验证；生产未发布，生产开关保持默认关闭。

## 请求与响应契约

服务端目标由 `WEBSITE_IDENTITY_URL` 配置；生产启动强制校验为 `https://arboradmin.saikr.com/miniapp/me`，本地联调固定使用 `http://127.0.0.1:8001/miniapp/me`，空体 `POST`，发送 `Accept: application/json`、`Authorization: Bearer <凭证>` 与 `token: <同一凭证>`。适配器发送两个凭证头，不假定其中任一个可省略，不转发浏览器 Cookie、内部管理员身份、Origin 或个人资料。第二个凭证头由第一个推导，不接受两份不一致的输入。

成功结构如下，ID 为虚构示例：

```json
{"success":true,"message":"成功","data":{"id":12345}}
```

只有 HTTP 200、`success` 严格为布尔值 `true` 且 `data.id` 为正整数时建立身份。身份映射为稳定提供方命名空间与经上游校验的 ID；默认命名空间为 `arborseek-production`，启用并产生客户数据后不得随意变更。昵称、电话、头像、角色和统计数据不参与授权、不保存；官网 `role` 不能赋予助手内部管理员权限。ID 跨环境、删除后复用规则仍需官网确认。

## 助手校验行为

`WEBSITE_IDENTITY_ENABLED=false` 为默认值，提交凭证时返回 503；没有任何客户凭证的请求继续按签名游客 Cookie 处理。即使校验关闭，提交的客户凭证也不能悄悄降级为游客。

启用后的请求入口每次向官网校验，不跨请求缓存成功身份，不本地解码 JWT 来授权，不使用客户端账号 ID 或官网 `token` 头单独建立身份。若同时提供 `Authorization` 和 `token`，两者须一致；重复、空白、格式异常或超长凭证拒绝为 401，不发送上游。

- 上游 HTTP 401 → 助手 401，清理前端旧视图并要求重新登录。
- 上游超时、网络故障、429、5xx、重定向、未知 403 或未确认的业务失败 → 助手 503，拒绝操作；不猜测未公开业务码。
- 响应结构错误、超大响应或非预期 ID 类型 → 503，不建立客户主体。
- 请求目标固定、TLS 验证开启、禁止跟随重定向，凭证只发往配置的身份接口；生产必须使用上述官方 HTTPS 接口；不输出凭证或上游个人资料。

响应没有已确认的令牌有效期字段。`WEBSITE_IDENTITY_MAX_REQUEST_SECONDS` 默认 300 秒，是**本次助手请求的本地最长执行期限**，不是 JWT 有效期或登录会话时长；超时后不得输出或写入。后续请求重新校验，敏感写入取得行锁后再次校验，逐项/最终回答输出前再次校验，同一凭证返回不同 ID 时拒绝当前请求。上游拒绝后只清理当前失败请求的未完成认领，不能保存回答、修改他人咨询或延长历史期限。

这些检查只能在官网实际返回失效时拒绝；上游仍接受旧凭证时，助手无法从该接口识别一次未被撤销的退出。验证与业务提交之间也不具备跨系统原子性，不能承诺零延迟撤销。写入行锁期间校验最长受 `WEBSITE_IDENTITY_TIMEOUT_SECONDS` 限制（默认 3 秒）；上线前还需确认上游配额与容量，未执行真实负载验收。

## 本地结果与生产剩余事项

本地命名空间为 `arborseek-local`，与生产的客户主体隔离。使用两个虚构账号验证了 `/miniapp/me` 返回不同 ID、PHP 注销后旧 JWT 返回 401，以及 PHP 不可用时 Agent 返回 503。官网通过 `ArborseekAgentAuth.getCredential()` 向同源 `/agent/` API 发送当前 Authorization；不传用户 ID 或角色作为授权依据。

登录前只调用 `getLoginContext()` 读取当前咨询；认证成功后才挂起旧视图并关联该咨询。官网等待 Agent 同步最多 3 秒，超时中止关联/配置请求并提示，不能阻塞官网登录。参见[身份事件接入](官网身份事件接入.md)。

生产启用前仍需验证部署版本的撤销保证、过期/改密/封禁/刷新行为、所支持的 `ts_` 凭证类型、ID 稳定性和接口容量。生产灰度、真实课程资料、网关、隐私政策及 ARM64 资源验收均未完成。本地测试不替代这些条件。

配置见 `.env.example`；所有权与保留规则见[身份归属契约](官网客户身份与历史归属.md)。
