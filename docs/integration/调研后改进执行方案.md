# 调研后改进执行方案

更新日期：2026-10-09。状态：执行方案；平台验证尚未执行，未选择或安装替代平台。本方案细化[全站接入实施计划](官网全站接入实施计划.md)的执行顺序，不改变已确认首发范围与准出标准。历史基线保留在[上线评审](../operations/LAUNCH_REVIEW_2026-10-09.md)。

## 新增官网 API 资料后的计划修订

依据新提供的[课程助手接口说明](../yuanbao-course-assistant-api.md)和[CLI 说明](../tstj-cli-guide.md)，官网鉴权类型已明确为 JWT / `ts_`，且均绑定 `members.id`。身份任务由“确认使用何种登录方式”收窄为“补齐可验证的身份接口、响应及失效契约，再实现适配器”。接口说明基于官网源码整理，线上配置与本项目联调仍未完成；不得据此标记身份任务完成或调低估算。

1. **优先补齐身份契约。** 按已更新的[负责人问题清单](官网会员接入_负责人问题清单.md)获取脱敏请求/响应、稳定 ID 约束和 JWT / `ts_` 退出撤销规则。`/miniapp/open/me` 已知用于 CLI AK/SK 本人查询，尚无证据可用于客户 Bearer 验证。
2. **课程查询只做候选适配。** 外部 Tool API 不调用大模型，可避免通过官网聊天再生成一次回答；但所有外部 Tool 均需客户登录。保留现有游客目录和事实来源，获得真实响应后再验证 `search_courses` 的 ID、价格单位、在售语义和类型映射。个人 `get_my_courses` 中有效期属于该用户学习数据，不可用作全体访客的课程观看期限承诺。
3. **不直接串联两套聊天服务。** 官网 `/miniapp/ai/agent/chat` 固定 SSE，包含自己的模型、工具调用与历史；本项目仍负责课程规则及会话所有权。若后续评估该聊天入口，须单独映射 SSE 事件、HTTP/业务/流内错误、历史保留和销售门禁，不能当作普通检索 API 替换。
4. **不扩张首发范围。** 已提供的订单、优惠券、已学课程等能力不自动加入本项目；`search_news` 虽在 Schema 内但没有外部同名 POST 路由，不能按工具名拼接 URL。源宝和课程任务学习助手均不作为售前历史主库。
5. **不执行资料中的运维和写入示例。** CLI 发布/修改和下载接口不是本次修改计划的执行步骤；特别是课程任务下载 GET 可能触发学习任务完成，不作为无副作用的接入探测。

MaxKB → FastGPT 最多 2 人日的知识库验证顺序保持不变：官网业务查询与知识版本治理是不同问题。优先独立完成 PostgreSQL 验证及身份适配设计，真实接口未齐部分继续列为阻塞。

## 1. 目标与本次调整

用户补充确认：官网已有登录账号，全部是普通账号，没有会员等级或付费会员身份。首发对接现有普通账号，不新建会员体系、不检查会员权益；登录用户的跨设备续聊目标保留。此前“会员”指外部登录客户的措辞已纠正。

完整首发包含官网登录用户识别、当前游客咨询关联、本人跨设备续聊；课程限定 42、43、99。1 人投入，10 月底交付内部候选版与证据包；全部准出通过后才能公开灰度，必要时延后。

依据[公开仓库调研](../research/官网售前助手_公开仓库调研_2026-10-09.md)，调整为“保留现有业务闭环，限时验证成熟知识库能力，凭实测决定局部复用”。不把近期有版本发布等同于适合本项目，不因平台提供登录、公开应用 Key 或网站组件就认定官网登录用户隔离已满足。

本次具体变化：

- 在继续开发前增加最多 2 人日的选型验证，优先验证 MaxKB，FastGPT 作为对照；该顺序只是减少切换成本的执行选择，不表示性能优劣已定。
- 初次验证只覆盖资料导入、检索引用及问答 API。整套 UI、登录用户体系与历史迁移不作为月底前默认工作。
- 将课程业务规则与可替换检索服务的责任写清；只为实际通过验证的接入点增加适配，不预先重写所有模块。
- 先处理身份隔离、审核和资料撤回，再处理一般体验；性能优化必须从当前版本实测定位。
- 在线坐席平台移到后续需求：目前仍沿用顾问入口与备用联系渠道，不把 Chatwoot 安装列为首发前置项。

## 2. 自研与复用的边界

### 现有业务层继续负责

1. 官网身份验证适配、游客与登录用户所有权、当前咨询的原子关联、退出与账号切换、历史保留与删除。官网凭证由服务端校验，不能以浏览器传入的 userId 授权。
2. 课程资格范围、审核/在售状态、硬性适配条件、实时价格来源、购买链接与人工出口校验。模型或工作流不能绕过这些检查。
3. 事实权威来源、冲突裁决、有效版本和撤回。模型输入和最终答案均受课程资格约束，不能先全库检索再仅隐藏购买按钮。
4. 当前官网组件、SSE、回答快照、幂等与迟到回答保护。没有证据证明迁移收益前保持现有链路。

### 候选平台只验证可替换能力

MaxKB/FastGPT 优先验证正文解析、知识分片、检索与引用、调试记录及管理操作。若采用，通过服务端适配器访问，浏览器不持有平台管理凭证；平台不成为第二套登录用户历史主库。是否禁用其会话存储、如何删除残留及日志保留须在采用前确认。

接入契约至少包含：请求编号、允许课程及资料版本、问题、超时；响应包含答案依据、课程标识、文档/版本/片段定位和错误状态。若平台只能在生成后过滤资格或不能证明版本隔离，不接入正式咨询链路。具体接口以验证过的候选版本为准，本节不宣称已有这些接口。

DocsGPT、Dify 保留为后续候选；本轮不同时部署五个平台。Chatwoot 仅在确有在线坐席及值守安排时单独评估；顾问二维码不宣称为在线接管。

## 3. 最多 2 人日的验证与决策

### 验证准备

- 固定现有基线、候选正式版本/镜像摘要、模型与生成参数、资料版本及案例期望；记录环境和资源。现有系统也跑同样案例，才能比较收益。
- 从现有案例中人工复核至少 20 个，覆盖三门课的明确事实、多轮选课、未知项、冲突、价格查询失败、购买门禁、提示注入和旧资料撤回；资料缺项的正确结果是需确认，不能为演示补造答案。
- 只使用可用于测试的资料、合成账号和问题；隔离数据库、端口与凭证，禁止修改生产审核状态。先核对许可证与所需功能是否包含在可用版本，商业依赖未解决则停止该候选。

### 顺序和时间上限

1. 第 1 人日：建立现有系统对照结果；验证 MaxKB 安装、三门课导入、API、引用和资料版本隔离。单个候选安装排障最多半人日，超过即记录问题，不挤占登录用户实现时间。
2. 第 2 人日：用同一资料与案例验证 FastGPT；汇总部署耗时、人工处理步骤、失败案例、所需服务与资源、备份升级及集成缺口。来不及完成的项标为未验证，不能按通过处理。
3. 累计达到 2 人日立即结束本轮选型。没有候选通过采用条件，继续现有后端；不自动追加 Dify/DocsGPT 轮次。后续采用需要新的证据。

### 采用条件（全部满足）

- 需要的能力确实能通过可用版本 API 调用，许可与实际部署用途不存在未解决条件；没有必须临时采购才能完成的核心功能。
- 课程/资料版本隔离、撤回、未知与冲突处理、购买规则等安全场景全部满足；严重错误为零。最小样本仅供选型，不能替代最终准出样本。
- 答案质量不低于同条件现有基线；性能记录首个有效答案与整轮 p50/p95、错误率和样本数。不把处理进度事件算作首个有效答案。
- 按实际剩余任务拆分估算：可减少的开发/维护人日大于接入、资料重建、回归、备份升级及回滚增加的人日；列出估算依据及不确定项。
- 可以先局部接入并用配置切回现有检索路径；若答案快照、来源标识或用户数据需要不可逆迁移，本轮不采用。

交付一份选型记录：版本、步骤、原始结果、通过/失败/未验证项、剩余工作估算、采用或继续现有实现的理由。没有结果之前，默认实施路线仍是现有系统。

## 4. 单人执行窗口与每阶段交付

日期为目标窗口；选型耗时计入原排期，不额外承诺两套系统。官网或审核条件缺失时转做独立可验证项，延期项如实进入证据包。

1. **10/09–10/13：有限验证与依赖收口。** 执行上述最多 2 人日验证并形成结论；把已有负责人问题清单交用户转询，整理三门课缺项与原始证据。交付：选型记录、明确的复用边界、身份/课程/环境阻塞清单。不得把 PoC 当成上线实现。
2. **10/14–10/20：登录用户归属与权限闭环。** 按已确认契约实现所有者模型、迁移、关联和前后端失效处理，验证 A/B 隔离、重复与并发关联、退出、删除和迟到回答。官网协议未到时以受控适配器验证内部逻辑；真实身份接入保持未完成。候选如通过，仅在节省总工作量的前提下接入检索能力，不延后权限工作。
3. **10/21–10/26：三门课治理与恢复。** 形成权威事实版本、审核状态、撤回与缓存/索引失效闭环；准备生产资料存储并执行数据库与文件联合恢复、真实 PostgreSQL 迁移与并发验证。如采用外部知识库，其索引备份或重建也纳入恢复记录。
4. **10/27–10/30：冻结与证据包。** 固定代码、镜像、配置及资料版本；人工质量签收、实际模型 1/5/10 并发采样、官网端到端、恢复和回滚。缺真实环境的项目明确列未完成，交付内部候选版及风险清单。
5. **10/31：准出评审。** 五类 P0 全部通过才允许 5% 灰度；否则保持关闭并更新下一里程碑。后续 25%、100% 各按既定至少 7 天观察，不承诺月底全量。

## 5. 验收与降级

- **登录用户安全：** 当前选中、未过期且未删除的游客咨询才可关联；不批量带入其他游客记录。关联后退出不得凭原游客 Cookie 读回。每次读写核对所有权，真实官网双账号与跨设备验收必做。
- **课程业务：** 42/43/99 审核及购买入口、专属与备用联系人均有证据；观看期限冲突和硬件缺项不能通过生成文案“解决”。未审核课程保持关闭。
- **资料一致性：** 生效、撤回、旧片段、引用版本和缓存同步验证；恢复后核对文件哈希、条目数量、有效版本和核心问题。不能仅以知识库导入成功签收。
- **质量容量：** 沿用人工准确率至少 95%、任务完成率至少 90%、严重错误零的门槛；记录分母、评阅人、日期和失败案例。实际容量/延迟门槛仍需结合实测和业务要求确认。
- **运行失败：** 候选检索服务超时或不可用时不输出猜测答案；仅允许使用仍有效且已审核的确定性事实，其他情况明确提示暂不可用并提供有效人工出口。不得重新启用已撤回资料或沿用过期价格。
- **回滚：** 采用前先验证切回原检索路径；登录用户归属和已保存回答不随检索切换丢失。应用镜像回滚必须核对数据库兼容，不能假定自动降级迁移安全。

## 6. 需要用户配合与下一步

已有[官网负责人问题清单](官网会员接入_负责人问题清单.md)，无需重新回答已确认的首发和关联规则。下一次需要补充的是：

1. 官网服务端身份校验协议、稳定登录用户 ID、失效/退出规则及双测试账号、预发布条件；由用户转询，当前尚无真实协议。
2. 三门课资料裁决与审核权限、43/99 观看期限、42 硬件要求、有效购买页与真实顾问/备用出口。若用户有正式审核权限，可据证据签收；缺少依据的字段保留待确认。
3. 执行实际模型调用、临时部署或生产接入前，如缺可用环境、模型额度、存储或所需费用范围，及时提出具体问题；当前文档修订不代表已经部署或产生费用。

可立即独立执行的下一项：固定对照资料和案例、建立选型记录，再按时间上限验证候选；同时准备登录用户所有者模型与迁移设计。所有功能实现和准出完成状态仍维护在[当前实现](../architecture/current-system.md)，本方案不冒充完成记录。
