# 官网身份变化与助手视图清理

日期：2026-10-09。状态：助手侧通知桥和清理已实现并通过受控回归；尚未接入官网真实认证、撤销及实际登录回调，不代表生产登录已打通。

## 当前执行范围

用户已确认官网暂时无法修改，且尚未加载本项目助手脚本。因此独立助手页面无法观察官网的登录、退出或切号，当前不会增加跨站令牌读取或把轮询 `/miniapp/me` 当作退出检测。先通过助手服务 `/consult` 验证游客咨询，会员校验保持默认关闭，自动关联及会员跨设备历史暂缓，见[游客接入路径](游客接入.md)。以下通知契约保留，供官网具备接入条件后使用。

本次浏览器对比确认退出后“注册/登录”按钮重新出现，但未观察到新增后端接口地址或 `/miniapp/logout`。这不是完整网络抓包，无法据此断言绝无请求。公开[首页布局代码](https://www.arborseek.com/assets/js/MainLayout-tMLFaxik.js)调用用户状态的退出方法；[共享代码](https://www.arborseek.com/assets/js/app-shared-DsfTSUEn.js)中的该方法清除本地令牌和用户状态，没有调用声明的退出接口。此证据限于本次读取的前端版本及首页退出路径，尚未确认服务端退出接口的方法与响应。

## 官网侧需要接入的位置

官网完成登录、退出或切换账号，且新的服务端会话已生效后，调用：

```js
try {
  await window.ArborseekAgent?.identityChanged();
} catch {
  // 身份复核失败时助手保持关闭；官网可在恢复后再次通知。
}
```

也可发送通知事件：

```js
window.dispatchEvent(new Event('arborseek:identity-changed'));
```

这是本项目新增的接入接口，**不是已经确认存在的官网事件名称**。不传账号 ID、角色、令牌或用户资料；事件的 `detail` 不参与授权。真实凭据如何安全到达助手后端，仍须按官网确认的协议实施；当前组件只使用同源 `credentials: include`，不读取官网 localStorage 中的令牌。

可等待的函数调用失败会抛错；事件形式在组件内处理失败并保持关闭。组件初始化完成后才暴露 `ArborseekAgent`，宿主页应在脚本就绪后通知。初始灰度关闭时仅保留隐藏容器和通知桥，没有咨询入口；新身份通过服务端门禁后才能挂载。

## 清理与重新加载

通知到达时同步隐藏并移除旧视图和弹层，清空当前咨询、消息、草稿、历史列表、搜索、改名状态及分页引用；中止旧组件的普通请求与流式读取。移除助手所有身份分区的咨询定位键及旧版 `arborseek-consultation` 键，不删除官网自己的存储。已排队的输入框更新结束后再卸载旧组件，避免输入事件与卸载同一时刻发生时的组件异常。

随后重新请求 `GET /widget/config`。此接口根据服务端验证主体返回 `identity_kind` 与 `identity_key`：前者用于文案，后者是服务端所有者键的 SHA-256 摘要，只作浏览器缓存分区和变化检测，不接受其作为身份授权输入，不返回会员 ID 或凭证。配置与历史请求禁用缓存，服务端相关接口也返回 `Cache-Control: no-store`。

新配置有效且通过灰度后重新挂载并读取新主体的历史列表，不自动选择最近咨询，不从旧定位键恢复消息。并发多次通知只允许最后一次配置重新挂载；旧配置、历史、创建、改名、删除及 SSE 响应即使忽略取消而迟到，也不能写回新视图或浏览器存储。HTTP 或 SSE 的 401 会清理旧主体并重新复核；复核失败保持关闭。

同源其他标签页通过只含随机标记的 `arborseek-identity-revision` 存储通知同步清理，接收方不重复广播。重新聚焦或从后台恢复页面时再复核服务端身份。通知与聚焦复核不能代替服务端逐请求鉴权，也不是实时撤销协议；缺少官网通知时，前台持续展示的页面不能保证立即发现外部退出或封禁。

当前通知桥负责安全清除视图，不执行官网登录、退出或令牌撤销。当前游客咨询关联仍由已有 `POST /widget/conversations/{id}/associate` 事务接口处理；登录时捕获并关联选中咨询的真实流程，需在身份传递和官网回调明确后接入，不能把清理函数调用当作关联成功。

这些测试没有调用官网真实登录或撤销接口，真实双账号跨设备签收仍未完成。
