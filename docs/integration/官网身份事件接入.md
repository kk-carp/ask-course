# 官网身份变化与助手视图清理

日期：2026-10-13。状态：本地官网与 PHP 已完成密码登录、身份透传、当前游客咨询关联、刷新历史、双账号隔离和在途退出验证；生产未发布，生产开关保持默认关闭。

## 官网凭证与登录接入

本地官网已加载 Widget；普通开发和生产仍须显式启用 `VITE_PRESALES_IDENTITY_ENABLED`，默认不转发官网凭证。宿主页注册 `ArborseekAgentAuth.getCredential()`，Widget 每次请求读取最新值，仅发送到当前页面同源的 `/agent/` API，不自行持久化凭证。

`getLoginContext()` 只返回当前选中的游客咨询 ID，不清理存储、卸载组件或广播。输入错误密码不会破坏咨询。官网认证成功后先 `prepareIdentityChange()` 挂起并清理旧视图，再写入新凭证，调用 `identityChanged({associateConversationId, signal})`。只关联捕获的当前咨询；无选中咨询不自动关联其他记录。

官网等待可选的咨询同步最多 3 秒；超时会触发 AbortSignal，组件取消关联和配置请求。即使请求忽略取消而迟到，也不能重新挂载视图。超时或 409 显示同步失败，不宣称关联成功；官网登录本身继续完成。

退出、401 清理和切号后调用 `identityChanged()`，立即清除旧状态并复核新身份。主动退出还调用 PHP 注销，失败时警告并继续离开原页面；组件清理不能代替服务端撤销。官网的 Token `storage` 监听由主入口负责，关闭 Agent 后多标签登录状态仍会同步。

也可发送 `arborseek:identity-changed` 通知；事件不携带凭证、账号 ID、角色或资料，`detail` 不参与授权。独立 `/consult` 页面不会自动读取官网其他源的登录状态。

## 清理与重新加载

通知到达时同步隐藏并移除旧视图和弹层，清空当前咨询、消息、草稿、历史列表、搜索、改名状态及分页引用；中止旧组件的普通请求与流式读取。移除助手所有身份分区的咨询定位键及旧版 `arborseek-consultation` 键，不删除官网自己的存储。已排队的输入框更新结束后再卸载旧组件，避免输入事件与卸载同一时刻发生时的组件异常。

随后重新请求 `GET /widget/config`。此接口根据服务端验证主体返回 `identity_kind` 与 `identity_key`：前者用于文案，后者是服务端所有者键的 SHA-256 摘要，只作浏览器缓存分区和变化检测，不接受其作为身份授权输入，不返回会员 ID 或凭证。配置与历史请求禁用缓存，服务端相关接口也返回 `Cache-Control: no-store`。

新配置有效且通过灰度后重新挂载并读取新主体的历史列表，不自动选择最近咨询，不从旧定位键恢复消息。并发多次通知只允许最后一次配置重新挂载；旧配置、历史、创建、改名、删除及 SSE 响应即使忽略取消而迟到，也不能写回新视图或浏览器存储。HTTP 或 SSE 的 401 会清理旧主体并重新复核；复核失败保持关闭。

同源其他标签页通过只含随机标记的 `arborseek-identity-revision` 存储通知同步清理，接收方不重复广播。重新聚焦或从后台恢复页面时再复核服务端身份。通知与聚焦复核不能代替服务端逐请求鉴权，也不是实时撤销协议；缺少官网通知时，前台持续展示的页面不能保证立即发现外部退出或封禁。

当前通知桥负责安全清除视图，不执行官网登录、退出或令牌撤销。当前游客咨询关联仍由已有 `POST /widget/conversations/{id}/associate` 事务接口处理；官网本地流程已接入该关联接口；清理函数调用不代表关联成功，仍以接口结果为准。

上述受控回归不依赖实际 PHP；另有本地 Edge 和 HTTP 验收覆盖真实密码登录、注销、双账号隔离及独立客户端恢复。生产及真实多设备签收仍未完成。
