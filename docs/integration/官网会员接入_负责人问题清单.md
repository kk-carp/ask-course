## 可直接转发

我们准备接入官网咨询助手，支持游客提问、登录后保存当前咨询、跨设备查看本人历史。使用现有普通账号，不涉及会员等级、订单或支付。

麻烦确认以下事项，有接口文档或代码位置直接提供即可：

1. **登录校验**：已知官网助手接受 JWT / `ts_`。独立助手后端应调用哪个接口验证当前客户并取得 `members.id`？请提供方法、路径、请求头及成功/未登录/失效/故障的脱敏响应（含 HTTP 状态和业务码）。若采用本地 JWT 验签，请补签名算法、公钥获取、issuer/audience 与撤销契约；`ts_` 应如何验证？
2. **账号 ID**：已知两种凭证映射 `members.id`。请确认该 ID 跨设备稳定、删除后是否复用，以及是否需要区分租户或环境；校验响应通过哪个字段返回它？
3. **登录失效**：JWT 与 `ts_` 各自有效期、刷新和撤销规则是什么？官网退出、改密或封禁是否使两者都失效？校验接口是否限流、允许缓存多久？
4. **前端通知与传递**：登录、退出、切换账号有哪些事件或回调？官网如何将登录凭据安全交给独立助手后端；是否支持同源后端验证或一次性交换码？不要求用户把令牌写进 localStorage。
5. **测试条件**：能否提供测试站点和两个普通测试账号？助手访问校验接口有什么网络或认证要求？
6. **页面接入**：能否在全站加载助手脚本，并将同源 `/agent/` 转发到助手服务？请提供页面框架、路由方式、Cookie 配置（不含真实值）及 CSP 限制。
7. **流式回复**：代理能否支持 SSE，关闭缓冲和缓存，读取超时至少 180 秒？
8. **部署安排**：助手、数据库和资料文件放在哪里？谁负责页面接入、部署、备份恢复和回滚？预计何时可联调？

请优先回复 1–5 项。账号凭证和密钥通过受控渠道提供，不写进问题回复。

若后续复用课程 Tool，再补：`search_courses` 的脱敏完整响应、价格单位及字段语义、稳定课程 ID/类型映射、业务错误码、限流作用范围；外部 Tool 是否计划提供独立匿名公开查询。本轮不要求接入个人订单、优惠券或学习进度。

## 对接边界

- 仅关联当前选中且有效的游客咨询，不导入其他游客历史。
- 关联后退出，原游客身份不能再读取该咨询。
- 普通官网账号与助手内部管理员分开授权。
- 真实接口、测试环境和账号验证通过前，不视为完成接入。
