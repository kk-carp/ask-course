1. 背景与目标

1.1 业务背景

官网 www.arborseek.com 承载天树探界自有课程（价格带 ¥4.9–¥1600，分 6 大类）的展示与在线支付。课程支持在线支付，需先登录；支付完成后学员可见班主任企业微信，进入班级服务。

当前成交主路径为：售前人员在微信上与学员一对一沟通 → 引导至官网完成支付。由此形成三个基本事实：

  1. 官网承担的是"收银台"角色，决策与信任建立发生在微信；
  2. 付费前的唯一官网承接点，是"点击咨询 → 弹出该课程对应售前企业微信二维码 → 扫码加好友"，完整动作共五步，覆盖窄、依赖人工在线；
  3. 对自行找到官网的自然流量，付费前没有任何选课辅助——只能对着课程列表自行判断。

1.2 产品目标

总目标：把"扫码"从第一步变成最后一步。

先在官网内部用 Agent 完成常规答疑与选课推荐，只把价格让利、B2B 采购与复杂个案交给扫码转人工。Agent 是人工售前的同伴，不替代人工。

层面目标达成标志
学员侧降低选课决策成本面对课程体系与专业术语时，能在官网内得到带理由的推荐，无需先加微信
售前侧减少重复答疑，把人工产能留给高价值对话常规问题由 Agent 先行承接；交付给人工的线索已明确意向课程与画像
业务侧让自然流量被承接，并形成可归因的线索资产自然流量在官网内被接住；每条线索可追溯来源与最近人工接触人

1.3 成功指标与目标值状态

官网当前无任何基线数据，因此指标分两阶段推进：阶段一只采集不考核（MVP 上线后 2–4 周建立分层基线），阶段二基于基线设定目标值。全部指标按自然流量 / 售前引流两套口径分层统计。

口径提醒
官网订单中相当一部分由售前引流产生。若不分层直接看"官网转化率"，会把人工的功劳算到 Agent 头上，或反过来掩盖 Agent 的真实增量。
待补 · PL-04 目标值 各指标的目标值与验收阈值，待阶段一分层基线产出后回填。责任方：产品 + 数据。

1.4 范围边界

本期做（MVP）
  • 接入与入口：独立部署 + 脚本注入挂载、入口归一
  • 对话与问诊：4–5 轮结构化问诊、已决策用户短路径
  • 推荐：规则匹配 + LLM 生成理由，输出 2–3 门课
  • 知识库：9 板块 + 售前语料组织、板块深链
  • 转化：低价体验课 CTA、登录态引导与会话保持
  • 转人工：复用现有弹窗、按课程取售前码
  • 线索：来源标记、归属数据记录
  • 数据：完整埋点体系
  • 内部端：售前推荐与话术查询
  • 内容：课程正文与板块内容文本化（前置任务）
本期不做
  • 集团级跨品牌推荐（深蓝学院、优研升等）——仅推荐天树探界自有课程
  • K12 在线留资——涉未成年人信息，暂不开放
  • 会话内支付闭环——支付仍走官网原有链路
  • 优惠券 / 折扣自动发放——涉营销授权边界，列入 V2
  • 新建 IM 或在线客服系统——复用官网现有二维码弹窗
  • 售后链路——付费后由班主任承接，Agent 不介入

2.3 关键场景（按频次与价值排序）

  1. 选课困惑（最高频）：面对 ROS2、VLA、具身智能、仿真抓取等术语，学员无法判断自己该从哪门开始。
  2. 不愿扫码的自然流量：学员想先了解清楚再决定要不要加微信。
  3. 非工作时段咨询：学生晚间与周末是咨询高峰，与人工服务时段天然错配。
  4. 临门一脚的摩擦：已被预热、目标明确的学员回到官网，仍需自行完成登录与下单。
  5. 售前重复劳动：价格、难度、基础要求类问题被反复回答，缺少可复用的标准答案与快速推荐工具。

4. 流程说明

4.1 主流程 · 自然流量

1
进入官网并触发入口
首页 / 课程列表 / 课程详情页均可唤起；详情页可携带当前课程作为上下文
2
欢迎语与意图识别
判断属于"要选课"还是"问具体问题"；识别是否已指定课程或带售前来源参数
3
问诊（4–5 轮）
采集身份、技术基础、学习目标、硬件条件；其余维度（专业、时间投入、预算、证书诉求）在对话中自然补齐
4
硬匹配过滤
以课程目录 + 适用人群 + 难度分级做硬性过滤，剔除不匹配课程（如无设备不推实机实训营）
5
软排序与推荐输出
按目标契合度、价格带、时间投入加权取 Top 3；必须体现"先低价试 → 再升单"的阶梯关系并说明理由
6
转化动作
推荐卡片 → 课程详情页 / 低价体验课购买入口；回答具体疑问时深链对应板块锚点
7
登录 + 支付
未登录时引导登录；登录前后完整保留会话、画像与推荐记录
8
未成交则沉淀线索
保留会话与画像；命中转人工规则时按课程交付给对应售前

4.2 短路径 · 售前引流用户

1
来源识别
通过链接来源参数或对话中的明确表述，识别"已被售前预热"或"已指定课程"
2
跳过问诊
不得强制其重新完成问诊流程；直接给出该课程购买入口、开课信息与关键条款确认
3
降频处理
对带售前来源标记的访客降低主动唤起频次与力度，避免与售前形成重复打扰
4
兜底承接
若学员在购买环节仍有疑问，按 M6 转人工规则交付给该学员最近一次接触的售前

4.3 转人工流程

1
触发条件判定
四类触发：敏感意图命中（价格让利 / 退费 / 发票 / B2B）· 连续 2 轮知识库未命中 · 学员主动要求找人工 · 已购学员的售后诉求
2
确定候选售前
优先规则：该学员最近一次人工接触的售前；其次：按意向课程取该课程对应售前；再次：兜底码
3
取二维码
调用课程详情接口读取 pre_sale_service_qrcode；字段为空或校验失败时展示兜底码
4
展示弹窗并递送上下文
复用官网现有弹窗；同时将画像、意向课程与咨询摘要推送至对应售前（接口未开放时在弹窗内展示可复制摘要）
5
落库与时效告知
线索落库；非工作时段明确告知预计响应时间，不得以"已转人工"作为终止状态而不交付
6
回填与核对
售前侧回填实际接触结果，用于归属判定覆盖率核对与线索质量复盘

4.4 登录中断与恢复流程

1
未登录状态下发起购买
不丢弃任何上下文，先冻结当前会话状态
2
引导登录
说明登录目的（完成购买 / 查看已购），跳转官网 /login
3
登录完成返回
自动恢复至原流程，画像、推荐记录、待购课程全部保留
4
登录后话术切换
读取 is_enrolled / purchased_chapter_ids；已购学员停止推荐，转向售后服务引导

4.5 异常与边界流程

场景系统行为
知识库未命中（连续 2 轮）停止自动应答 → 走转人工流程；不得编造答案继续作答
敏感意图命中立即停止自动应答 → 转人工；统一口径为"该项需人工确认"
非工作时段展示兜底二维码 + 告知预计响应时间；线索落库，次一工作时段交付
课程接口异常 / 字段缺失使用缓存数据并在界面标注"信息可能非最新"；售前码字段为空时展示兜底码
某课程线线索量达上限对该课程线降级呈现（兜底码或降低推荐权重），并记录限流事件
同一会话内重复主动唤起禁止；同一访客在一次会话周期内只主动唤起一次
学员明确表示"不想聊了"立即收起，不追问、不挽留；记录退出原因
B2B / 高校采购意图不走课程推荐；收集基本需求信息后转商务侧，或引导至独立留资表单
K12 相关咨询本期不承接在线留资；仅提供公开信息，不做信息采集
已购学员的售后问题不推荐课程；引导至班主任售后服务通道（付费后可见）

5. EARS 需求描述

Ubiquitous · 普遍约束

U-01 · R3
数据真实性
系统应始终基于课程接口与知识库的真实数据生成推荐与课程信息，不得编造课程名称、价格、开课时间、师资、证书效力与优惠内容。
U-02 · R4
付费内容边界
系统应始终拒绝输出付费课程的视频内容、逐字稿，或任何可绕过付费保护的信息；知识库只使用详情页介绍级材料。
U-03 · R3
推荐范围
系统应始终仅在天树探界自有课程范围内推荐，不得推荐集团其他品牌或外部机构的课程与赛事。
U-04 · R6
转人工判据
系统应始终以"人工答得更好"作为转人工判断标准，而非"机器答不出来"。
U-05 · R9
上下文不丢失
系统应始终保证会话、画像与推荐记录在页面跳转（含登录跳转）后不丢失。
U-06 · R8
承诺边界
系统应始终不承诺折扣、退费、包就业或证书效力；涉及此类内容时统一转人工。

Event-driven · 事件驱动

E-01 · R11 / R19
主动唤起
当访客在课程详情页连续停留超过 30 秒且未点击购买时，系统应主动展示售前助手入口，并以该课程为上下文生成开场白；若该访客带有售前引流来源标记，系统应降低主动唤起频次。
E-02 · R22
点击咨询入口
当学员点击归一后的"咨询"入口时，系统应先由 Agent 承接一次问询；仅当学员坚持要求人工、或提问命中转人工规则时，才应展示售前人员二维码。
E-03 · R20
指明课程
当识别到学员在对话中指明具体课程名称时，系统应加载该课程上下文并进入短路径判定，不再询问已可从上下文获得的画像信息。
E-04 · R28
内容缺失告警
当课程内容文本化尚未覆盖某门课程时，系统应对该课程降低推荐权重，并在回答相关内容时明确提示"该课程详情请查看页面说明"，不得凭课程标题推测内容。

State-driven · 状态驱动

S-01 · R2 / R3
问诊完成态
当会话已采集到"学员身份、技术基础、学习目标"三项必要信息时，系统应输出不少于 2 门、不多于 3 门课程的推荐，并附上每门课的适配理由与价格差异说明。
S-02 · R20
已决策态
当系统识别到学员已明确指明目标课程，或该学员由售前人员引导进入时，系统应跳过问诊环节，直接提供该课程的购买入口、开课信息与关键条款确认，不得强制其重新完成问诊流程。
S-03 · R6 / R24
转人工路由态
当触发转人工时，系统应依据学员的意向课程，从课程详情接口取对应售前人员的二维码展示；若该课程无对应售前，或所需售前不在服务时段，系统应展示兜底二维码或通用联系方式，不得展示空白弹窗或与课程无关的售前。
S-04 · R9
已购学员态
当接口返回该学员已报名或已购章节时，系统应停止课程推荐，转为引导至班主任售后服务通道。
S-05 · R27
归属判定态
当存在多笔人工接触记录时，系统应按最近一次人工接触的售前输出归属建议，并同时标注该次接触的时间与渠道，供管理侧核对。
S-06 · R24
课程线限流态
当某课程线的当日线索量达到承载上限时，系统应对该课程线降级呈现（改用兜底码或降低推荐权重），并记录限流事件供运营复盘。

Unwanted · 异常处理

X-01 · R9
登录中断
如果学员在未登录状态下发起购买或点击下单，则系统应保留当前会话、画像与推荐记录，并在登录完成后自动恢复至原流程，不得要求用户重新发起咨询。
X-02 · R8 / R23
敏感意图
如果学员的提问涉及价格让利、退费承诺、发票开具、B2B 采购合作，或连续 2 轮无法被知识库匹配，则系统应立即停止自动应答，复用官网现有的二维码弹窗展示该课程的售前人员企业微信，并将画像与咨询摘要同步推送至对应售前（企微接口未开放时，退化为在弹窗内展示可复制的摘要）。
X-03 · R6
非工作时段
如果学员在非售前工作时段发起转人工，则系统应明确告知预计响应时间并保留会话与画像，且应保证线索落库后于下一个工作时段被交付，不得以"已转人工"作为终止状态而不交付。
X-04 · R24
接口异常
如果课程详情接口调用失败或关键字段缺失，则系统应使用缓存数据并在界面标注信息可能非最新；若售前二维码字段为空或校验失败，则系统应展示兜底码，不得展示空图或与课程无关的二维码。
X-05 · U-01
幻觉自检
如果生成的回答引用了知识库与课程接口之外的信息，则系统应拦截该回答，改用兜底话术或转人工，不得直接将未校验内容输出给学员。
X-06 · R11
重复唤起
如果同一访客在一次会话周期内已被主动唤起过，则系统不得重复主动唤起。
X-07 · R19
来源不可判定
如果无法判定学员的来源渠道，则系统应标记为"来源未知"并单独统计，不得默认计入自然流量，以免污染自然流量组的基线。

Optional · 可选能力

O-01 · R19
来源参数
在链接带售前引流来源参数的场景下，系统应读取该参数并标记线索来源，用于分层统计与降低重复打扰。
O-02 · R21
售前内部端
在售前使用内部端的场景下，系统应提供按学员画像查询推荐结果、标准话术与课程对比的能力，并支持一键复制。
O-03 · R10
板块深链
在学员询问"适合什么人群""有没有证书""怎么上课"等问题时，系统应同时给出文字回答与该详情的板块锚点链接。

6. 交互说明

6.1 入口与挂载

  • 挂载方式：脚本注入，Shadow DOM 样式隔离；iframe 作为保守备选。
  • 入口形态：全站悬浮球，覆盖首页、课程列表、课程详情。
  • 入口归一（R22）：现有"咨询"按钮与悬浮球合并为一个入口，先 Agent 后扫码，不再并存两个功能相似的入口。
  • 上下文感知：在课程详情页打开时，解析 /course/:courseId 并与课程接口数据比对，作为问诊起点。

6.2 对话形态

  • 开场：按上下文区分——详情页内以当前课程开场；列表页/首页以"帮你选课"开场。
  • 问诊：关键问题以选项卡片形式给出（可点选，也可自由输入），降低作答负担；轮次控制在 4–5 轮。
  • 信息补齐：专业背景、时间投入、预算、证书诉求通过对话自然获取，不额外增加问诊轮次。
  • 随时退出：允许中途退出，保留已采集的画像。

6.3 推荐卡片

字段来源说明
课程名称 / 副标题title / subtitle不加工、不改写
价格与原价price / original_price需统一类型后展示（见 PL-03）
标签tags[]含颜色值，直接渲染
难度difficulty_level（1–3）转为"零基础 / 有基础 / 进阶"表述
适配理由规则命中结果 + 课程真实字段必须引用真实字段（适用人群、课程目录、学习安排），不得泛泛而谈
阶梯关系同名产品的体验课 / 正价课配对需说明两者关系与递进路径
行动按钮—低价体验课优先；正价课给购买入口

6.4 转人工弹窗

  • 复用现有弹窗，不新建通道；弹窗内展示：售前二维码、承载人身份说明、预计响应时间、加好友备注模板。
  • 加好友备注模板可复用接口 tutor.remark 字段。
  • 弹窗内展示可复制的咨询摘要（企微推送接口未开放时的降级方案），供学员转发或内部留档。
  • 弹码不等于问题已解决：弹窗须明确告知后续由人工跟进，并保证线索已落库。

6.5 文案与语气规范

类别规范
语气专业、平实、不夸张；不使用"包学包会""保证就业"等承诺性表述
价格话术只引用接口真实价格与优惠；倒计时类紧迫感表述必须与实际规则一致，不得虚构截止时间
不确定时明确说明不确定并建议转人工，不猜测
统一口径Agent 与售前共用同一话术库；价格、优惠、退费等敏感项以官方口径为准

6.6 状态清单

状态界面表现
加载中显示思考态，超过预期时长给出等待提示
知识库未命中明确说明并给出转人工入口，不编造
接口异常标注"信息可能非最新"，关键操作仍可继续
转人工降级展示兜底码 + 通用联系方式
非服务时段展示二维码并告知预计响应时间
课程线限流对该课程改推兜底码，不向用户暴露限流原因
空态（无匹配课程）如实说明没有完全匹配的课程，给出最接近的 1 门或建议转人工

8. 权限与合规

8.1 角色权限

角色可访问内容限制
未登录访客公开课程信息、知识库问答、推荐、低价 CTA不可查看订单与已购状态；购买前须登录
已登录学员上述全部 + 已购状态识别已购学员不推课，转售后引导
售前人员内部端：按画像查询推荐结果、话术、课程对比可见范围限于本人负责课程线；不可见他人线索与业绩明细
课程运营知识库条目维护（V1）、内容完整度视图不可修改价格与优惠口径
销售管理者课程线线索分布、归属判定覆盖率与明细用于核对，不直接改写归属结果
产品 / 数据全量埋点与会话数据会话内容使用受合规口径约束（见 8.2）

8.2 合规红线

红线要求
付费内容保护严禁输出课程视频内容、逐字稿或可绕过付费保护的信息（课程视频为腾讯云 DRM 加密）
虚假促销不得虚构优惠截止时间、库存或名额；倒计时表述必须与实际价格规则一致
承诺越权不得承诺折扣、退费、包就业、证书效力
未成年人本期不承接 K12 在线留资；如后续开放需完成监护人同意流程
会话内容留存为支撑线索归因与转人工摘要需保留会话内容，须明确允许范围、保留期限与对用户的告知方式
客户资产线索与客户关系沉淀于企业微信侧，不得留存于个人账号
待补 · PL-05 会话内容留存口径 允许留存的字段范围、保留期限、脱敏要求与用户告知方式。注意：既有同类系统（FDE）的隐私设计为不记录问题全文，本项目需求与之相反，需明确反向调整的依据。责任方：产品 + 法务 / 合规。

9. 非功能需求

类别要求
性能首字响应时间与推荐生成时间需满足对话体感要求；接口调用失败须有降级与缓存
可用性非工作时段仍可提供服务；Agent 不可用时不得影响官网原有浏览与下单链路
注入隔离Shadow DOM 隔离样式与脚本，不得影响官网自身样式与行为；可直接摘除
兼容性覆盖主流桌面与移动端浏览器；移动端需适配弹窗高度与输入体验
可维护性知识库条目、课程线承载上限、转人工触发规则均可配置，不需发版
可观测性会话链路可追踪；接口异常、限流、兜底码启用等事件可告警
安全售前二维码、线索与归属数据按角色最小权限访问

10. 验收标准

需求验收条件验证方式
R22 入口归一官网上不存在两个功能相似的入口；点击归一后的入口先进入对话，仅在触发转人工规则时才出现二维码功能验收 + 页面巡检
R2 问诊完成三项必要信息的采集不超过 5 轮；每轮均可通过点选完成用例回归
R3 推荐输出 2–3 门课；每条推荐均引用真实课程字段作为理由；存在体验课/正价课配对时同时呈现并说明关系抽样评审 + 规则校验
R4 / R28 知识库Top 20 课程的常见问题覆盖率达标；未命中时明确说明并转人工，无编造内容评测集跑批 + 人工抽检
R9 登录保持未登录发起购买 → 登录 → 返回后会话、画像、待购课程完整保留全链路用例
R24 售前码按意向课程取到的二维码与该课程配置一致；字段为空时展示兜底码；上线前完成全课程覆盖校验接口比对 + 覆盖报表
R6 转人工四类触发条件均可正确触发；转人工后线索落库，且非工作时段有明确的时效告知用例 + 落库核查
R20 短路径带售前来源参数或已指定课程时问诊轮次为 0，直接呈现购买入口与条款确认用例回归
R8 敏感意图敏感意图命中后不再自动作答；无承诺性回复对抗用例
R19 / R27 归属成交订单可输出"最近一次人工接触售前 + 时间 + 渠道"；无法判定的单独口径统计数据核对
R21 内部端售前可按画像查询推荐结果与话术并一键复制；权限限于本人课程线功能验收
R7 埋点7.2 事件全部可采集；可按来源分层出数埋点验收清单
待补 · 目标值类验收条件 上述各项的量化阈值（覆盖率、准确率、响应时间等）待阶段一基线产出后回填。见 PL-04。
