# 成熟项目补充对标：从功能具备到可运营

核查日期：2026-10-09（Asia/Shanghai）。本文保留官方仓库与官方文档的对标依据，合并替代早期候选列表；执行顺序见[改进计划](../development/roadmap.md)。未部署第三方产品，未实测准确率、延迟、可靠性或迁移成本，不按 Star 排名。本次文档整理未重新联网核验，版本、许可和功能在实际选型前需再次确认。

## 结论与范围

**分析判断：本项目应借鉴成熟平台的身份验证、知识运营和问题复盘能力，不宜为“功能更多”整套迁移。** 保留 MaxKB 优先、FastGPT 对照、累计最多 2 人日的既有验证顺序。Dify 是工程与运营能力参考，Chatwoot 是未来有真实坐席需求时的客服参考；两者不加入本月部署清单。单人、课程 42/43/99、10 月底内部候选版的约束不变。

以下“事实”是来源明确声明的能力；“启示”是本项目适配判断。平台有某能力，不证明其社区版、指定版本或默认配置满足我们的业务。

## Chatwoot：客服产品，借鉴人工交接与身份边界

**事实：** AgentBot 通过 Webhook 接收会话事件，再通过 API 回复。接入机器人后新会话处于 pending，机器人可切为 open 将会话转给人工；接管保留会话上下文。因此实际人工接管包含会话状态和坐席工作台，并非仅显示联系方式。[AgentBot 官方说明](https://app.chatwoot.com/hc/user-guide/articles/1677497472-how-to-use-agent-bots)

**事实：** 官方明确区分联系人匹配与身份验证：填写邮箱或用户 ID 不能证明拥有该身份；服务端生成签名，密钥不能放浏览器。网站收件箱可要求所有会话带有效身份令牌，缺失或无效会被拒绝。[联系人身份与验证](https://www.chatwoot.com/hc/user-guide/articles/1782283175-understanding-contact-identity-and-identity-validation-in-chatwoot)

**事实：** 自托管免费社区版不含 Captain AI、细粒度角色权限和 SSO；付费功能范围需看版本。官方列出 Linux、PostgreSQL、Redis，以及文件对象存储等部署条件。[自托管功能与部署条件](https://www.chatwoot.com/pricing/self-hosted-plans)

**启示：** 本月借鉴“后端验证官网身份，再授权历史”的边界。游客咨询关联、退出后失权、跨设备归属仍按本项目契约实现。现阶段继续顾问入口；只有确认值守安排后才增加 `bot / waiting / human / resolved` 状态、交接回执和机器人停答机制。本轮未验证其知识审核或课程销售门禁，不能用 Captain 替代这些规则。

## Dify：AI 应用平台，借鉴过滤与运行复盘

**事实：** Dify 支持以自定义元数据筛选检索资料；官方源码存在 metadata filtering 处理。该机制提供筛选手段，不自动定义谁能看哪门课、哪个版本可生效。[官方功能介绍](https://dify.ai/zh/blog/dify-v1-1-0-filtering-knowledge-retrieval-with-customized-metadata)、[检索节点源码](https://github.com/langgenius/dify/blob/main/api/core/workflow/nodes/knowledge_retrieval/knowledge_retrieval_node.py)

**事实：** 官方日志页面说明可查看真实会话或运行、用户及运营反馈、Token 与延迟、原始提示和逐节点轨迹；Workflow 支持用运行输入重测。Chatflow/Workflow 编辑器测试不计入这些生产日志。该文档含云端套餐保留规则，不能直接套到自托管。[Logs 文档](https://docs.dify.ai/en/cloud/use-dify/monitor/logs)

**事实：** 当前许可证在 Apache 2.0 基础上附加多租户及前端标识条件；租户按 workspace 定义。不能把它简称为无限制 Apache 2.0。[仓库许可证](https://github.com/langgenius/dify/blob/main/LICENSE)

**启示：** 本项目最有价值的借鉴是一次请求可追到允许课程、资料版本、命中片段、模型/提示版本、耗时、失败位置及反馈，再转成回归案例。元数据资格应由已验证的业务条件确定，不能交给模型自由推断。平台日志中的 end-user 标识不能自动替代官网登录授权。Dify 不作为完整客服坐席或本月新增迁移对象。

## FastGPT：知识问答与编排平台，借鉴引用解释和评测

**事实：** 引用阅读器可查看原文并定位片段，提供相关性信息；免登录场景可限制为仅引用内容可见，全文导出受阅读权限约束。[引用分块阅读器](https://doc.fastgpt.io/zh-CN/guide/chat/quoteList)

**事实：** 官方应用评测 Beta 文档支持批量问答、标准答案与历史记录、逐条输出及评分。页面明确当前测试版仅有回答准确性指标，不能把列出的未来指标当成已交付。[应用评测文档](https://doc.fastgpt.io/zh-CN/guide/build/evaluation)

**事实：** 官方将其定位为知识处理、RAG 和可视化工作流平台。许可证附加类似 FastGPT 的多租户 SaaS 与控制台标识条件；是否获得特定商业能力应另核实。[仓库](https://github.com/labring/FastGPT)、[许可证](https://github.com/labring/FastGPT/blob/main/LICENSE)

**启示：** 引用应能验证答案，至少展示文档名称、版本、片段定位与有效状态，外部用户不能因点击引用而获得整份内部材料。自动评测适合加速回归，不替代三门课事实签收和严重错误人工审阅。PoC 需验证这些能力实际可用版本、API 与撤回行为；此轮资料没有证明安全续聊或完整人工坐席可开箱即用。

## MaxKB：保留既定首选，仅验证可替换知识能力

**事实：** 官方仓库列出文档上传/网页抓取、切分向量化、RAG、工作流、MCP 与业务系统嵌入；技术栈为 Vue、Python/Django、PostgreSQL + pgvector，提供 Docker 快速启动，主体许可为 GPLv3。[官方仓库](https://github.com/1Panel-dev/MaxKB)

**核查限制：** 本轮搜索索引能返回 v2 文档管理页摘要，但直接打开该页及 v2 根路径返回 404，因此不据此新增细粒度功能结论，也不用 v1 文档冒充 v2。知识编辑、命中测试、日志、权限、撤回的指定版本实际行为留给 PoC，许可适用性按真实部署和分发方式核对。

**启示：** 保留 MaxKB 优先的理由是延续已定执行顺序及相近运维栈，绝非已经证明优于 FastGPT。不要因为 Vue/Python 相近就估算可直接迁移 FastAPI；仍需通过服务端适配器隔离平台及用户历史。

## 将对标转为可验收的修改项

以下为建议，实际代码差距以本项目当前实现核查为准；不将文档任务自动视为未实现。

1. **身份与历史优先：** 后端校验官网普通账号，所有历史读写验证所有权。验收覆盖 A/B 隔离、仅关联当前游客咨询、重复/并发关联、退出、删除与迟到响应。借鉴 Chatwoot 的身份验证原则，不新增会员体系。
2. **资料生效与撤回：** 每次检索限定业务允许访问的课程和有效资料版本，引用保留稳定定位；方向相关展示与销售审核资格继续分开。撤回同时验证索引、缓存和新回答失效，历史回答明确保留当时来源。元数据过滤是实现手段，课程业务层是权威。
3. **请求复盘最小闭环：** 以请求编号串联检索、模型、回答与反馈，记录来源版本及阶段延迟；低质量回答可加入人工复核案例。避免直接复制复杂工作流编辑器。
4. **限时 PoC：** 沿用既有 20 个以上人工复核案例，以同模型和资料对比现有系统、MaxKB、FastGPT；记录错误、引用、撤回、权限、延迟和总维护成本。资料隔离或撤回失败即不接正式链路，无证据不迁移。
5. **人工与平台扩张后置：** 本月保持真实有效的顾问/备用入口；在线人工接管、全渠道、团队角色、可视化编排均在明确需要后单独估算。第三方安装成功不替代 PostgreSQL 并发、恢复与回滚演练。

本轮新增的是可追溯的参考依据，没有安装候选平台、改变上线范围或验证生产质量。
