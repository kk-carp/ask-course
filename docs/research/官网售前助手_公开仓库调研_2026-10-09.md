# 官网售前助手：公开 GitHub 仓库调研

调研日期：2026-10-09（Asia/Shanghai）。范围：知识库售前问答、网站嵌入、会话与客户身份、人工承接、自托管。基于 GitHub 官方仓库、发布记录及产品官方文档；本轮未部署这些项目，也未实测其准确率、性能或迁移成本。

## 结论

值得优先评估的五个项目是 **FastGPT、MaxKB、Chatwoot、DocsGPT、Dify**。均查到 2026 年 9 月或 10 月的正式发布，且发布记录有功能或工程修复，不只是 README 更新。这里“做得好”指功能产品化、持续发布、文档与部署/集成入口完整，属于候选筛选判断，不是对生产可靠性的实测背书。

对本项目的优先级建议属于分析判断：

- 快速验证知识库与选课流程：先比较 **MaxKB 与 FastGPT**，只选一个作为候选底座。
- 真正接入在线顾问坐席：优先看 **Chatwoot**；不要把提供二维码视为与在线人工接管等价。
- 参考文档问答组件和检索后端：看 **DocsGPT**，并可评估官方已有的 Chatwoot 桥接。
- 需要通用工作流、模型接入和运营观测平台：看 **Dify**。

公开仓库不等于所有功能都免费，后台 SSO 也不等于官网访客已经能安全续聊。真实课程资料签收、官网身份契约与生产验收仍需我们完成。

## 1. FastGPT：知识库售前与对话编排优先候选

[仓库](https://github.com/labring/FastGPT) · [README](https://github.com/labring/FastGPT/blob/main/README.md)

- 已有能力：文档导入、混合检索与重排、可视化对话工作流、引用反馈、调用日志、免登录分享及 iframe 嵌入。这些是官方列出的产品能力，适合承载“课程资料问答 → 收集条件 → 分支处理”。
- 维护证据：[v4.17.1](https://github.com/labring/FastGPT/releases/tag/v4.17.1) 发布于 **2026-09-30**，此前 v4.17.0 为 09-11。新版本有资源权限、知识库标签、引用、会话标题、并发写入等改进。
- 最值得借鉴：知识分片修改、调试轨迹、结构化条件筛选、对话运营记录。发布版本治理可参考，但不能直接等同于课程事实审核与冲突裁决。
- 边界：[LICENSE](https://github.com/labring/FastGPT/blob/main/LICENSE) 在 Apache 2.0 基础上增加条款，涉及类似平台的多租户 SaaS 和控制台标识。功能还区分社区与商业版；本轮没有证明完整会员续聊与人工坐席可在社区版直接满足我们的要求。
- 对我们的适配判断：适合优先做知识库和多轮选课 PoC；课程销售门禁、实时价格与购买校验保留为明确业务接口。

## 2. MaxKB：中文应用与接近现有技术栈的候选

[仓库](https://github.com/1Panel-dev/MaxKB) · [官方文档](https://maxkb.cn/docs/v2/index.html)

- 已有能力：RAG、可视化工作流、模型适配与业务系统嵌入。仓库技术栈为 Vue、Python/Django、PostgreSQL + pgvector，与我们相近，但后端框架不同，不能理解为直接兼容现有 FastAPI 代码。
- 维护证据：[v2.10.6-lts](https://github.com/1Panel-dev/MaxKB/releases/tag/v2.10.6-lts) 发布于 **2026-09-03**；[版本页](https://github.com/1Panel-dev/MaxKB/releases)显示连续 LTS 修复，包含工作流功能及游客会话归属等修复。近期修复说明仍维护，不证明不存在其他缺陷。
- 最值得借鉴：知识库运营入口、表单/工作流组织、业务系统嵌入、中文管理体验。
- 边界：仓库为 [GPLv3](https://github.com/1Panel-dev/MaxKB/blob/main/LICENSE)；[官方版本对比](https://maxkb.cn/price)区分社区、专业及企业版，不能默认所有第三方集成与认证能力均包含在社区版。后台认证和官网客户历史归属要分别验证。
- 对我们的适配判断：是单人快速验证成品平台的优先候选；是否能减少月底工作量，需通过实际安装、同样案例与权限流程确认。

## 3. Chatwoot：客服坐席与人工接管优先候选

[仓库](https://github.com/chatwoot/chatwoot) · [社区版说明](https://www.chatwoot.com/community)

- 已有能力：网站聊天窗口、共享客服收件箱、客服分配、会话、自动化和报告。相对当前二维码交接，它提供的是实际在线客服工作台。
- 维护证据：[v4.18.0](https://github.com/chatwoot/chatwoot/releases/tag/v4.18.0) 发布于 **2026-09-18**；此前 v4.17.1 为 08-27、v4.17.0 为 08-20，具有持续版本记录。
- 客户身份参考：[官方联系人 API](https://developers.chatwoot.com/api-reference/contacts-api/update-a-contact)有外部 identifier 与 HMAC identifier_hash。可参考身份签名边界，但仍须验证具体 Widget 的强制校验配置、退出与历史行为，不能仅调用 setUser 或传 userId 就认为身份安全。
- 边界：[社区版 MIT、企业目录另有许可](https://app.chatwoot.com/hc/user-guide/articles/1677776492-enterprise-edition)。按[当前自托管版本说明](https://www.chatwoot.com/pricing/self-hosted-plans)，免费社区版不包含 Captain AI；Captain 在付费自托管方案中。这里的坐席 SSO 不能当作官网客户登录能力。
- 对我们的适配判断：当首发目标包含顾问在线接管时价值高；如仅需二维码和备用链接，整套客服平台可能增加运维和迁移成本，需实测后决定。

## 4. DocsGPT：文档问答、嵌入组件与 Chatwoot 桥接

[仓库](https://github.com/arc53/DocsGPT) · [官方概览](https://docs.docsgpt.cloud/)

- 已有能力：带引用的文档问答、多模型、API、自托管，提供 [React/HTML 聊天组件](https://docs.docsgpt.cloud/Extensions/chat-widget)。可借鉴检索服务、流式交互与组件集成。
- 维护证据：实时打开发布页查到 [v1.0.0](https://github.com/arc53/DocsGPT/releases/tag/1.0.0)，发布于 **2026-10-08**；包括备份恢复、Widget 移动端、引用和可观测性改进。搜索缓存仍显示 09-16 的 v0.21.0，以发布页为准。
- 人工接管路径：[官方 Chatwoot 扩展](https://docs.docsgpt.cloud/Extensions/Chatwoot-extension)提供桥接，并用 `human-requested` 标签停止机器人回复。它是额外运行的扩展，不代表单独部署 DocsGPT 就有完整客服坐席。
- 边界：主体仓库声明 MIT；Widget 属于单独分发组件，采用时核对实际包版本和许可。[Agent API Key 文档](https://docs.docsgpt.cloud/API/agent-keys)明确网页 Widget 的 Agent Key 是公开的，它不是官网会员授权凭证。
- 对我们的适配判断：适合作为较聚焦的问答候选或 Chatwoot 的配套；仍需自建课程准入、客户归属和销售规则适配。

## 5. Dify：通用 AI 编排后端

[仓库](https://github.com/langgenius/dify)

- 已有能力：工作流、RAG 管线、模型接入、应用日志与 API，适合用作业务应用背后的 AI 编排平台。官方提供自托管入口。
- 维护证据：[1.17.1](https://github.com/langgenius/dify/releases/tag/1.17.1) 发布于 **2026-09-10**；此前 1.17.0 为 08-25。新版本有知识库 API Key 等更新及明确升级要求。
- 最值得借鉴：工作流与业务 API 分离、模型可替换、调试及运行观测。它是应用平台，不应预设为完整客服系统。
- 边界：[Dify License](https://github.com/langgenius/dify/blob/main/LICENSE)有多租户和前端标识附加条件；[仓库](https://github.com/langgenius/dify)对企业 SSO/RBAC 另列企业方案。平台登录与外部客户授权必须区分。
- 对我们的适配判断：适合平台化与后续扩展，未必比 MaxKB/FastGPT 更省当前单人迁移工作。

## 初筛但未列为优先替代的方向

- [Hexabot](https://github.com/hexabot-ai/Hexabot)：原 Hexastack 地址已跳转，当前 README 定位为 v3 工作流/Agent/渠道统一运行平台。没有完成本轮版本、坐席与许可核验，不据此推荐直接迁移。
- [ChatterMate](https://github.com/chattermate/chattermate.chat)：README 明确面向 AI 客服、网站组件与人工交接，值得下一轮深入；本轮没有取得足够的维护与生产交付证据，暂不与上面五个同等推荐。
- 搜索结果中的个人演示项目不因最近抓取、声称“production-ready”或简单脚本嵌入而自动进入短名单。

## 对现项目的建议

以下为调研后的判断，尚未作迁移决策或变更已确认首发范围：

1. **先做 1–2 个工作日的隔离 PoC**，比较 MaxKB 与 FastGPT；采用相同三门课资料、相同模型与已人工复核的案例，记录部署耗时、首项/整轮延迟、事实与引用正确性和权限行为。这里是建议的验证预算，不是已经执行的工作。
2. **单独评估人工需求**：若要顾问在线接管，再验证 Chatwoot + 现有后端，或 Chatwoot + DocsGPT。两个平台组合会增加组件、存储和升级成本，不能预设更快上线。
3. **保留课程业务边界**：未审核课不能购买、实时价格来源、观看期限冲突、适配硬条件等必须在明确的业务层校验；本轮未找到可直接替代这些规则的现成证明。
4. **用同一身份验收场景比较**：会员 A/B 隔离、跨设备恢复、退出、仅关联当前游客咨询、删除与迟到回答。内部平台 SSO 或公开应用 Key 不等于满足这些场景。
5. 仅当候选平台明确减少剩余工作、且知识/会话迁移和回滚可验证，才讨论替换。否则保留现有系统，借鉴成熟平台的运营与交互设计。

## 核查限制

GitHub REST API 本轮返回匿名速率限制，因此不提供实时 Star 排名、提交频率或贡献人数。维护判断使用正式发布页及发布中的功能/修复记录；日期额外从发布页 HTML 的 `relative-time datetime` 核对。本轮没有安装或运行第三方仓库，不能给出实测可靠性排名。
