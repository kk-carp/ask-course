## 服务结构

[服务入口](../../backend/main.py)挂载健康检查、指标、认证、文档、问答、匿名问诊、会话和售前映射路由，启动时初始化数据库与向量模型。内部演示页面与官网嵌入脚本由 [spa.py](../../backend/spa.py) 托管。

咨询前端已迁移为 Vue 3 + Vite + Ant Design Vue 4.2.6，主题色为 `#1890ff`；公开页只显示右下角入口和展开后的问答面板，内部管理独立在 `/admin`。组件及 Ant Design Vue 弹层样式通过 Shadow DOM 隔离，构建产物位于 `frontend/dist`，Docker 自动构建。

全站脚本 `data-mode="site"` 已支持无课程页面与 SPA 上下文更新；默认签名游客 Cookie，官网问答不继承内部账号权限。`/widget/conversations` 提供本人会话创建、分页、改名与删除；`visitor_turns` 保存完整回答快照，最近三轮上下文单独存储。站点模式刷新后恢复会话，默认保留 24 小时，读取和改名不延期；删除立即失效，每 5 分钟物理清理。已完成提问通过幂等编号重放，删除后迟到回答不能恢复记录。本地内部预览仍使用页面内存历史。官网登录用户桥接未实现，详见[全站接入实施计划](../integration/官网全站接入实施计划.md)。

[ask.py](../../backend/routes/ask.py) 接收请求，[ask_orchestrator.py](../../backend/services/ask_orchestrator.py) 统一编排访客上下文与回答。[intent_router.py](../../backend/services/intent_router.py) 优先处理讲价退款发票、找顾问、付款和明确的选课请求。访客说出具体方向时先展示相关课程；只在方向不明或无法命中时追问目标。已推荐课程的基础、硬件和时间可继续补充，但不阻塞首次展示。其他课程问题优先查询实时商业字段或本地事实登记，适用时用官网文字快照补充公开概览；剩余正文问题由 [qa_service.py](../../backend/services/qa_service.py) 检索知识库。`/consultations` 保留结构化接口，官网组件使用统一的 `/ask` 多轮对话。

游客仅访问服务端限定的课程空间。自由问答与选课问诊共用匿名访客状态：最近三轮问答在服务端保留 24 小时，用于本地追问检索；短回答按上一轮问题解释，已确认的选课字段无需重复回答。历史原文不会作为对话消息发送给回答模型，回答仍只依据本轮检索片段。会话通过签名的访客 Cookie 隔离。知识库正文需要上传文本或可解析文档；官网列表和详情接口不代替正文入库，图片正文仍需先文本化。

问诊状态由 `consultation_service.dialogue_state` 统一读取，并过滤当前不可见课程；新会话显式保存 `_pending_field`，清除时写入 `null`。只有缺少该键的旧会话才通过上一轮话术兼容恢复，明确清除的状态不会被旧话术重新激活。整轮候选与非站点历史由 `complete_dialogue` 一次提交；站点回答快照和历史仍由幂等认领流程保存。

事实主题统一复用 `course_facts.fact_topic`，官网快照只补充概览、基础、硬件与公开授课方式，不能用简介回答开课日期或商业字段。语义理解和官网目录只对预期上游或数据解析错误降级，非预期程序错误继续向外报告。

[question_decomposition.py](../../backend/services/question_decomposition.py) 拆分带问号、逗号或常见连接词的明确并列问题，自我介绍与选课画像陈述保持完整。每个问题复用单问题编排，合并答案、依据、课程卡片与顾问入口；游客整条咨询保存为一轮。SSE 输出处理进度、逐项结果与最终答案；RAG 只保留统一的非 token 流式生成路径，语义模型调用集中在本轮理解中。多问题的 `/ask` 和 `/ask/stream` 均返回 `intent=multi_question`，`hit=true` 仅表示至少一项有依据，不能当作所有问题已解决。某一项上游服务暂不可用时保留其他答案，全部查询不可用则返回服务错误。价格与公开优惠优先读取官网可核实字段，最多缓存一分钟；过期后查询失败不沿用旧价格。观看期限等结构化事实读取本地事实登记，缺项或冲突明确提示需确认，未覆盖的正文问题再走检索；未接入官网有效期字段，也不把宣传快照当作已经审核的事实版本。

默认无方向首次咨询跳过课程目录拉取和语义模型。已确定课程且无画像变化、比较或修正的明确事实查询使用规则理解。游客对同一确定课程的独立内容问题最多三项并行，访客上下文在执行前统一准备，合并答案后只保存一轮历史；逐项事件和最终答案保持提问顺序。登录用户、混合推荐／付款意图和需要推进画像的查询保持串行。并行任务传播请求编号，便于关联审计日志。

管理员 `/metrics` 的 `latency_ms` 提供最近 500 个样本的 p50／p95：`ask_catalog`（目录）、`ask_understanding`（理解）、`ask_questions`（全部查询）、`ask_turn`（整轮）和 `ask_first_turn`（站点按是否已有完成消息，旧通道按是否携带会话 ID 判定）。结合已有 `embedding`、`retrieval_and_rerank`、`model` 指标与访问日志的 `duration_ms` 定位耗时；首次请求指标包括新会话，并不等同于进程冷启动。查询测试使用受控上游，实际提速需用部署环境指标验证。

## 文档替换与真实数据库验证

同空间、同内容哈希的 `replace` 上传先保留旧资料，候选文档完成保存、解析、向量化及切片写入后，在同一事务中下线旧文档并启用候选。保存、解析、向量化或数据库写入失败时，旧资料仍为 `ready`；原资料在处理期间被撤回或被另一替换更新时，候选拒绝发布并要求重新上传。并发普通重复上传返回重复文档冲突。该修复保留现有同哈希替换语义，不等同于不同内容资料的业务版本发布、审核或在途问答撤回控制。

CI 新增独立 `postgres-integration` 任务，使用 PostgreSQL 16 + pgvector，覆盖空库/旧库 Alembic 升级、真实向量与词法过滤、游客请求幂等与并发认领、删除锁与迟到回答，以及文档替换失败回滚和并发冲突。本地可通过 `TEST_POSTGRES_URL` 运行；测试要求专用库，拒绝已有 public 业务表，逐例创建和清理独立 schema。模型向量为受控测试数据，不调用官网或真实模型。CI 配置已加入仓库，GitHub 远端执行结果仍以实际工作流为准。

## 转人工行为

内容回答命中时直接返回。未命中但已找到相关课程候选时先引导选课；其他未命中情况尝试解析联系人。明确找顾问、讲价、退款和发票等意图直接进入人工承接流程。

[handoff_service.py](../../backend/services/handoff_service.py) 按以下顺序寻找有效出口：

1. 数字课程 ID 对应的官网详情售前码。
2. 本地 `topic_owners` 的课程 ID 精确映射。
3. 问题文本中的课程关键词映射。
4. `HANDOFF_FALLBACK_CONTACT` 配置的兜底联系人。

无有效出口、关闭转人工或解析异常时可能返回 `configured=false`。`hit=false` 不一定意味着已经成功转人工，调用方还需检查 `owner` 和 `related_courses`；系统故障也不能视为普通知识未命中。

## 配置与上线前提

配置入口为 [.env.example](../../.env.example)，完整定义和环境校验见 [config.py](../../backend/config.py)。`APP_ENV=prod` 拒绝默认密钥与默认演示密码，要求严格课程内容校验、启用人工承接并配置有效格式的真实兜底链接。格式校验不能证明联系人实际可访问，仍需运营核验。

课程正文、在售目录、负责人和真实售前映射按 [L0 手册](../operations/L0_OPERATIONS.md)准备。[官网试运行准出](../operations/PILOT_LAUNCH.md)另外要求课程审核清单、购买页和二维码核验。启动不再插入占位售前映射，并清理旧占位行。
